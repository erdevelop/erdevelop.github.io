Git ve GitHub Pages

Bir web sitesini sürüm kontrolüyle yönetmek ve GitHub Pages'te yayımlamak için kısa, 4 günlük ve bol şemalı bir program. İlk commit'ten dallara ve çakışmalara, yayından alan adına ve önbelleğe, hatalardan dönmekten birden çok kişi ya da araçla aynı depoda güvenli çalışmaya kadar.

7 güngünde ~4 saatTürkçeKod örnekleri kopyalanabilir

Başlamadan önce

Kimler için

Kendi sitesini ya da araçlarını yayımlamak isteyenler, kod ve çizim dosyalarının geçmişini tutmak isteyen mühendisler. Ön bilgi gerekmez; Web Araçları kursuyla birlikte iyi gider.

Gerekenler

  • Git (git-scm.com) ya da GitHub Desktop.
  • Ücretsiz bir GitHub hesabı.

GÜN 01

Git'e giriş

~3 saat · 0/5 kontrol

Hedef

Gün sonunda Git'in ne işe yaradığını, kurulumu ve ayarı, depo (repository) oluşturmayı, değişiklikleri kaydetmeyi (commit), geçmişe bakmayı ve hangi dosyaların Git'e girmeyeceğini (.gitignore) bileceksin. Süre yaklaşık 3 saat.

Bu kurs hakkında: 4 günlük kısa bir program. Bir web sitesinin dosyalarını sürüm kontrolüyle yönetmeyi ve GitHub Pages'te yayımlamayı öğretir. Komutlar Git 2.4x ile denenmiştir. Kursun sonunda Web Araçları kursunda yaptığın aracı kendi adresinde yayımlayabilirsin.

1. Git neden? (30 dk)

Sürüm kontrolü olmadan: site_son.zip, site_son2.zip, site_GERCEKTEN_son.zip. Git ile:

  1. Her değişikliğin ne, ne zaman, neden yapıldığı kayıtlıdır.
  2. Herhangi bir ana geri dönebilirsin.
  3. Denemeler ana sürümü bozmadan ayrı bir dalda yapılır.
  4. Birden çok kişi (ya da birden çok bilgisayar) aynı dosyalar üzerinde çalışabilir.
  5. GitHub ile yedek, paylaşım ve ücretsiz web yayını (GitHub Pages).

Git ≠ GitHub: Git bilgisayarındaki sürüm kontrol programıdır. GitHub, Git depolarını barındıran bir web sitesidir.

2. Kurulum ve ayar (30 dk)

  1. git-scm.com'dan Git'i kur (Windows'ta "Git for Windows"; Git Bash ile gelir).
  2. Bir kez adını ve e-postanı tanıt:
git config --global user.name "Ad Soyad"
git config --global user.email "ad@ornek.com"
git config --global init.defaultBranch main

Görsel araç tercih edersen GitHub Desktop ya da VS Code'un Kaynak Denetimi paneli aynı işleri butonlarla yapar. Bu kurs komutları gösterir, çünkü hangi düğmenin ne yaptığını anlamanın en kısa yolu budur.

3. Üç alan (45 dk)

Çalışma klasörü  →  git add  →  Hazırlık alanı (staging)  →  git commit  →  Depo (geçmiş)
  1. Çalışma klasörü: Dosyaların kendisi; düzenlediğin yer.
  2. Hazırlık alanı: Bir sonraki kayda girecek değişiklikler.
  3. Depo: Kayıtların (commit) geçmişi; .git klasöründe saklanır. Bu klasöre dokunma.

4. İlk depo ve ilk kayıt (45 dk)

cd site
git init                     # bu klasörü bir Git deposu yap
git status                   # ne değişti?
git add index.html           # tek dosyayı hazırla
git add .                    # ya da hepsini
git commit -m "İlk sayfa"    # kaydet
git log --oneline            # geçmiş:  8112136 İlk sayfa
git diff                     # henüz hazırlanmamış değişiklikleri satır satır gör

İyi bir commit mesajı ne yaptığını kısaca söyler: "Cam ağırlığı aracına CSV indirme eklendi" ✓, "düzeltmeler" ✗. Bir commit, tek bir mantıklı değişiklik olsun.

5. .gitignore (15 dk)

Bazı dosyalar depoya girmemelidir: geçici dosyalar, büyük çıktılar, kişisel ayarlar ve asla parolalar.

# .gitignore
.DS_Store
Thumbs.db
*.tmp
node_modules/
_egitim_kaynak/
.env

Yayımlanan bir depo herkese açıksa, içine giren her şey (geçmişte bir kez girmiş olsa bile) herkesin görebileceği yerdedir.

GÜN 02

GitHub

~3 saat · 0/4 kontrol

Hedef

Gün sonunda deponu GitHub'a gönderebilecek (push), oradan alabilecek (pull, clone), dal (branch) açıp birleştirebilecek ve basit bir çakışmayı çözebileceksin. Süre yaklaşık 3 saat.

1. GitHub'a göndermek (1 saat)

  1. GitHub'da yeni bir depo oluştur (boş; README ekleme).
  2. Bilgisayarındaki depoyu ona bağla ve gönder:
git remote add origin https://github.com/kullaniciadi/site.git
git push -u origin main      # ilk kez; sonrası yalnızca: git push
  1. Kimlik doğrulama: Git, tarayıcıda GitHub girişi ister (Git for Windows'un kimlik yöneticisi) ya da GitHub Desktop bunu senin yerine yapar. GitHub artık hesap parolasıyla komut satırı girişini kabul etmez.
Komut Ne yapar
git push Yerel kayıtları GitHub'a gönderir
git pull GitHub'daki yeni kayıtları alır ve birleştirir
git clone <adres> Bir depoyu ilk kez bilgisayara indirir
git fetch Yeni kayıtları indirir ama birleştirmez

Kural: Başka bir bilgisayarda ya da GitHub'ın web arayüzünde değişiklik yaptıysan, çalışmaya başlamadan önce git pull.

2. Dallar (1 saat)

Dal, ana sürümü bozmadan yapılan bir deneme hattıdır:

git switch -c yeni-tema      # yeni dal aç ve ona geç
# ... dosyaları değiştir, commit et ...
git switch main              # ana dala dön (değişiklikler burada görünmez)
git merge yeni-tema          # denemeyi ana dala birleştir
git branch -d yeni-tema      # artık gereksiz dalı sil

GitHub Pages genellikle main dalını yayımlar; bu yüzden yarım işleri ayrı dalda tutmak, sitenin bozuk hâlinin yayına çıkmasını engeller.

3. Çakışma (merge conflict) (45 dk)

Aynı dosyanın aynı satırı iki yerde farklı değiştirildiyse Git hangisini seçeceğini bilemez ve dosyaya işaret koyar:

<<<<<<< HEAD
<title>Cam Ağırlığı</title>
=======
<title>Cam Ağırlığı Hesaplama</title>
>>>>>>> yeni-tema
  1. Dosyayı aç, istediğin hâli bırak, işaret satırlarını (<<<<<<<, =======, >>>>>>>) sil.
  2. git add dosya ve git commit.

VS Code çakışmaları renkli gösterir ve "Accept Current / Incoming / Both" düğmeleri sunar.

Çakışmayı azaltmak için: Sık ve küçük commit, çalışmaya başlamadan git pull, aynı dosya üzerinde aynı anda iki yerde çalışmamak.

GÜN 03

GitHub Pages

~3 saat · 0/5 kontrol

Hedef

Gün sonunda bir siteyi GitHub Pages'te yayımlayabilecek, kendi alan adını bağlayabilecek, 404 sayfası, sitemap ve önbellek konularını bilecek ve yayından önce kontrol edebileceksin. Süre yaklaşık 3 saat.

1. GitHub Pages (1 saat)

Depo adı Adres
kullaniciadi.github.io https://kullaniciadi.github.io/ (kullanıcı sitesi)
Herhangi bir ad, ör. araclar https://kullaniciadi.github.io/araclar/ (proje sitesi)
  1. Depoda Settings → Pages.
  2. Kaynak: Deploy from a branch, dal main, klasör / (root) (ya da /docs).
  3. Birkaç dakika içinde site yayında. Her git push, yayını yeniden oluşturur; durum, deponun Actions sekmesinde görünür.

Ücretsiz plan notu: Ücretsiz hesaplarda Pages herkese açık depolardan yayımlanır; depo herkese açıksa içindeki her dosya da okunabilir (1. gün, .gitignore).

2. Yollar ve dosya adları (45 dk)

  1. Ana sayfa index.html olmalıdır; klasor/index.html ise …/klasor/ adresinde açılır.
  2. GitHub Pages sunucusu büyük-küçük harfe duyarlıdır: Tools.html ile tools.html farklıdır. Windows'ta çalışıyor diye yayında da çalışacağını varsayma.
  3. Proje sitesinde (/araclar/) / ile başlayan yollar alan adının köküne gider; göreli yol (css/site.css, ../index.html) kullan.
  4. Türkçe karakter ve boşluk içeren dosya adlarından kaçın.

3. Alan adı, 404 ve sitemap (45 dk)

  1. Kendi alan adın: Settings → Pages → Custom domain'e ornek.com yaz; alan adı sağlayıcında GitHub'ın belgelerindeki DNS kayıtlarını ekle; "Enforce HTTPS" kutusunu işaretle.
  2. 404 sayfası: Kökte bir 404.html dosyası, bulunamayan adreslerde gösterilir.
  3. Arama motorları: sitemap.xml (sayfaların listesi) ve robots.txt; Google Search Console'a sitemap'i bildir.

4. Önbellek ve "değişikliğim görünmüyor" (30 dk)

Push ettin ama değişiklik görünmüyor mu? Sırayla:

  1. Actions sekmesinde yayın bitti mi (yeşil tik)?
  2. Tarayıcı önbelleği: Ctrl+F5 ya da gizli pencere.
  3. Sitende bir service worker varsa (Web Araçları, 7. gün) eski dosyaları sunuyor olabilir; önbellek sürümünü değiştir.
  4. Doğru dalı ve doğru dosyayı mı push ettin? git log origin/main --oneline -3.

GÜN 04

Güvenli çalışmak

~3 saat · 0/5 kontrol

Hedef

Son gün hatalardan dönmeyi, sürüm etiketlerini, birden çok bilgisayar ya da yardımcıyla güvenli çalışmayı ve günlük bir Git alışkanlığını öğreneceksin. Süre yaklaşık 3 saat.

1. Geri almak (1,5 saat)

Durum Komut
Bir dosyadaki kaydedilmemiş değişikliği at git restore dosya.html
Yanlışlıkla hazırladığın dosyayı hazırlıktan çıkar git restore --staged dosya.html
Son commit mesajını düzelt (henüz push etmediysen) git commit --amend -m "Yeni mesaj"
Son commit'i geri al, değişiklikler dosyalarda kalsın (push etmediysen) git reset --soft HEAD~1
Yayımlanmış bir commit'i geri al git revert <commit>
Değişiklikleri bir kenara koy, sonra geri getir git stash · git stash pop
Eski bir dosya sürümünü getir git restore --source=<commit> dosya.html

En önemli kural: Push edilmiş geçmişi değiştirme (reset, --amend ile). Yayımlanmış bir hatayı revert ile düzelt: yeni bir commit hatayı tersine çevirir, geçmiş bozulmaz.

git reset --hard ve git clean kaydedilmemiş işi kalıcı olarak siler. Kullanmadan önce iki kez düşün.

2. Sürüm etiketleri (20 dk)

git tag -a v1.0 -m "İlk yayım"
git push origin v1.0

GitHub'da etiketten bir Release oluşturup notlar ve indirilebilir dosyalar (ör. bir programın kurulum dosyası) ekleyebilirsin.

3. Birden çok kişi, bilgisayar ya da yardımcı (40 dk)

Aynı depo birden çok yerde değiştiriliyorsa (iş ve ev bilgisayarı, bir iş arkadaşı, bir yapay zekâ yardımcısı ya da otomatik bir araç):

  1. Başlarken: git pull ve git status; beklemediğin bir değişiklik var mı?
  2. Commit etmeden önce: git diff ile her satırına bak. Senin yapmadığın bir değişiklik varsa, kimin yaptığını öğrenmeden gönderme.
  3. Sık ve küçük commit: Bir başkasının değişikliğiyle çakışma ihtimali azalır.
  4. Aynı dosyada aynı anda iki iş yapma: Özellikle bütün sitenin listelendiği tek bir ana dosya (ör. araç listesi sayfası) çakışmaların merkezidir.
  5. Büyük işleri dalda yap, bitince birleştir.

4. Günlük alışkanlık (30 dk)

git pull                         # 1. güncel ol
# ... çalış ...
git status                       # 2. ne değişti?
git diff                         # 3. satır satır kontrol et
git add <dosyalar>               # 4. yalnızca bu işe ait dosyaları hazırla
git commit -m "Ne yaptın"        # 5. anlamlı mesajla kaydet
git push                         # 6. yayımla

Sonra sitenin yayınlandığını (Actions) ve sayfanın açıldığını kontrol et.

Kursun sonu: Web Araçları kursunda yaptığın aracı bir depoya koy, GitHub Pages'te yayımla ve bağlantısını telefonundan aç.
