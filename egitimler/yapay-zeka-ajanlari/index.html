Yapay Zekâ Ajanları ve Otomasyon (n8n)

Yapay zekâyı sohbet penceresinden çıkarıp işlerin içine yerleştirmek için 7 günlük bir program. Bir ajanın modeli, araçları ve döngüsüyle nasıl çalıştığını küçük bir Python benzetimiyle görür, sonra açık kaynaklı otomasyon aracı n8n'i kurarsın. Tetikleyiciler, düğümler ve ifadelerle e-posta, tablo ve web servislerini birbirine bağlar; dil modeli düğümleriyle metinleri sınıflandırır ve içlerinden yapılandırılmış veri çıkarırsın. AI Agent düğümüne araç ve bellek verir, MCP ile ajanını başka araçlara açarsın. Son gün tedarikçi e-postalarını okuyan, sipariş tablosunu güncelleyen ve emin olmadığında insana soran bir ajan kurarsın.

Başlamadan önce

Kimler için

Tekrarlayan e-posta, tablo ve bildirim işlerini otomatikleştirmek isteyen mühendisler, teknik ofis ve operasyon ekipleri; yapay zekâyı sohbetin ötesinde kullanmak isteyen yazılımcılar. Programlama bilgisi şart değildir ama JSON'u okuyabilmek ve basit JavaScript ifadelerini anlamak işini kolaylaştırır. Yapay Zekâ ile Çalışmak eğitimi iyi bir ön hazırlıktır; Docker eğitimi kurulum için yardımcı olur.

  • Bir dil modeli API anahtarı (OpenAI, Anthropic, Google ya da Mistral) ve küçük bir kullanım bütçesi; ya da Ollama ile yerelde çalışan bir model.
  • 1. gün ve bazı denemeler için Python 3.

GÜN 01

Yapay zekâ ajanı nedir?

~4 saat · 0/6 kontrol

Hedef

Gün sonunda bir yapay zekâ ajanının dört parçasını (model, araçlar, döngü, bellek) bilecek; sohbet, sabit iş akışı ve ajan arasındaki farkı ayırt edecek; araç çağırmanın arka planda nasıl işlediğini küçük bir Python benzetimiyle görecek ve bir işin ajana mı yoksa sabit bir akışa mı uygun olduğuna karar verebileceksin. Süre yaklaşık 4 saat.

Bu kurs hakkında: İlk gün kavramları Python ile, sonraki günler her şeyi n8n ile yapıyoruz. n8n iş akışlarını kursta JSON olarak veriyoruz: kopyalayıp n8n editörüne Ctrl+V ile yapıştırınca akış olduğu gibi kurulur. Yapay zekâ içermeyen akışların çıktıları gerçek çalıştırma sonuçlarıdır. Dil modeli kullanan akışları ise, gerçek bir modelin yerine kurallı yanıt veren sahte bir model ile çalıştırdık (4. günde nasıl yapıldığını göreceksin); kendi modelinle aynı akış aynı adımları izler, metinler farklı olur.

1. Sohbetten ajana (45 dk)

Yapay zekâyı işte kullanmanın üç düzeyi var:

Sohbet Sabit iş akışı (otomasyon) Ajan

Öngörülebilirlik Yüksek (sen kontrol edersin) Çok yüksek Daha düşük

Ajan, bir hedef verildiğinde hangi adımları atacağına kendisi karar veren ve bu adımları araçlar aracılığıyla dünyada uygulayan bir yapay zekâ sistemidir. Dört parçası vardır:

  1. Model: Karar veren dil modeli (GPT, Claude, Gemini, Llama…).
  2. Araçlar: Modelin çağırabileceği fonksiyonlar: tablo oku, e-posta gönder, web'de ara, hesap yap.
  3. Döngü: Model düşünür → bir araç çağırır → sonucu görür → tekrar düşünür… hedefe ulaşınca durur.
  4. Bellek: Konuşmanın ve önceki adımların hatırlanması.

Önemli bir gerçek: Model hiçbir şeyi kendisi yapmaz. Sadece “şu aracı şu girdiyle çağır” diye metin üretir. Aracı çalıştıran, sonucu modele geri veren, döngüyü yöneten programdır (bu kursta n8n). Ajanın güvenliği ve güvenilirliği bu yüzden büyük ölçüde o programın tasarımına bağlıdır.

2. Araç çağırma nasıl çalışır? (1 saat)

Model API'sine istek gönderilirken mesajların yanında bir araç listesi de gönderilir: her aracın adı, ne işe yaradığı (açıklama) ve hangi girdileri aldığı (şema). Model yanıtında ya normal bir metin döner ya da “bu aracı şu argümanlarla çağır” der. Program aracı çalıştırır, sonucu bir “araç sonucu” mesajı olarak ekler ve modeli tekrar çağırır.

Bunu gerçek bir model olmadan, kurallı bir sahte modelle canlandıralım. Sahte model gerçek bir modelin vereceği türden kararları basit kurallarla veriyor; bizi ilgilendiren model değil, etrafındaki döngü:

import json
import re

# --- Araçlar: gerçek işi yapan sıradan fonksiyonlar
SIPARISLER = {
    "CAM-01": {"durum": "üretimde", "teslim": "2026-11-24", "adet": 120},
    "SLK-01": {"durum": "teslim edildi", "teslim": "2026-11-05", "adet": 60},
}


def siparis_durumu(kod):
    return SIPARISLER.get(kod, {"hata": f"{kod} bulunamadı"})


def gun_farki(tarih1, tarih2):
    from datetime import date
    a, b = date.fromisoformat(tarih1), date.fromisoformat(tarih2)
    return (b - a).days


ARACLAR = {
    "siparis_durumu": {"fonk": siparis_durumu, "aciklama": "Malzeme koduna göre sipariş durumunu verir. Girdi: kod"},
    "gun_farki": {"fonk": gun_farki, "aciklama": "İki tarih (YYYY-AA-GG) arasındaki gün sayısı. Girdi: tarih1, tarih2"},
}


# --- Sahte model: gerçek modelin vereceği türden kararları kurallarla verir
def sahte_model(mesajlar, araclar):
    soru = mesajlar[0]["icerik"]
    sonuclar = [m for m in mesajlar if m["rol"] == "arac"]
    kod = re.search(r"[A-Z]{3}-\d{2}", soru)
    if not sonuclar and kod:
        return {"arac": "siparis_durumu", "girdi": {"kod": kod.group(0)}}
    if len(sonuclar) == 1 and "montaj" in soru:
        teslim = json.loads(sonuclar[0]["icerik"])["teslim"]
        montaj = re.search(r"\d{4}-\d{2}-\d{2}", soru).group(0)
        return {"arac": "gun_farki", "girdi": {"tarih1": montaj, "tarih2": teslim}}
    return {"metin": "Bilgileri topladım: " + " | ".join(m["icerik"] for m in sonuclar)}


# --- Döngü: ajanı ajan yapan kısım
def ajan(soru, en_cok_adim=5):
    mesajlar = [{"rol": "kullanici", "icerik": soru}]
    for adim in range(1, en_cok_adim + 1):
        karar = sahte_model(mesajlar, {ad: a["aciklama"] for ad, a in ARACLAR.items()})
        if "metin" in karar:
            print(f"[{adim}] model yanıtladı -> {karar['metin']}")
            return karar["metin"]
        sonuc = ARACLAR[karar["arac"]]["fonk"](**karar["girdi"])
        print(f"[{adim}] model {karar['arac']}({karar['girdi']}) istedi -> {sonuc}")
        mesajlar.append({"rol": "arac", "icerik": json.dumps(sonuc, ensure_ascii=False)})
    return "Adım sınırına ulaşıldı."


ajan("CAM-01 siparişi ne durumda?")
print("---")
ajan("CAM-01 camları gelmeden montaja başlayamayız. Montaj 2026-11-20'de başlıyor; kaç gün beklememiz gerekir?")
print("---")
ajan("XYZ-99 nerede?")

Kodu okurken şunlara dikkat et:

  • Araçlar sıradan fonksiyonlardır. Modelin bildiği tek şey adları ve açıklamalarıdır (ARACLAR sözlüğündeki aciklama). Gerçek API'lerde bu açıklamalar modele gönderilir; model hangi aracı seçeceğine bu açıklamalara bakarak karar verir. 5. günde iyi araç açıklaması yazmayı göreceğiz.
  • Döngü en fazla 5 adım dönüyor (en_cok_adim). Bu sınır olmasa, kararsız kalan bir model aynı aracı sonsuza kadar çağırabilir ve faturanı şişirir.
  • İkinci soruda model iki aracı sırayla kullandı: önce teslim tarihini öğrendi, sonra o tarihle gün farkını hesaplattı. Bu sırayı kimse önceden çizmedi; ajanı sabit akıştan ayıran özellik budur.
  • Üçüncü soruda araç hata döndürdü ve model bunu olduğu gibi aktardı. Gerçek bir model de çoğu zaman öyle yapar; ama bazen hatayı “yorumlayıp” yanlış bir cevap uydurabilir. Araç hatalarının açık ve anlaşılır metinler olması bu yüzden önemlidir.

3. Bellek (30 dk)

Model durumsuzdur: her API çağrısında ona bütün geçmişi yeniden göndeririz. Yukarıdaki mesajlar listesi ajanın kısa süreli belleğidir. Gerçek uygulamalarda üç tür bellek vardır:

Bellek Ne tutar n8n'de
Konuşma belleği Aynı oturumdaki son mesajlar Simple Memory, Postgres/Redis Chat Memory
Uzun süreli bilgi Belgeler, şartnameler, geçmiş kayıtlar; gerektiğinde aranır Vector Store düğümleri (RAG)
Yapılandırılmış veri Siparişler, projeler, kişiler Bir tablo ya da veritabanı, araç olarak

Kural: Ajanın bilmesi gereken kesin veriler (sipariş durumu, fiyat) belleğe değil araca konur. Model onları hatırlamaya çalışmaz, her seferinde araçtan okur. Bellek, konuşmanın akışı için vardır.

4. Ajan ne zaman gerekmez? (45 dk)

Ajanlar heyecan verici ama çoğu iş için gereksiz ve risklidir. Karar için üç soru:

  1. Adımlar her seferinde aynı mı? Evet ise sabit akış kur. “Gelen e-postayı sınıflandır, tedarikçi gecikme bildiriyorsa tabloya yaz” her seferinde aynı adımlardır; içinde bir yapay zekâ adımı (sınıflandırma) olabilir ama ajan gerekmez.
  2. Yanlış bir adım ne kadar pahalı? Para ödemek, sipariş vermek, müşteriye e-posta göndermek gibi geri alınamaz işleri ajanın kendi başına yapmasına izin verme; ya sabit akışta tut ya da insan onayı koy (6. gün).
  3. Girdi ne kadar belirsiz? Kullanıcının serbest metinle her şeyi sorabildiği bir asistan (sipariş, stok, takvim, belge) gerçekten ajana ihtiyaç duyar.

Pratik yol: Önce sabit akış, içine yapay zekâ adımları; sadece adımların sırası gerçekten değişken olduğunda ajan. Bu kursun 2.–4. günleri sabit akışları, 5.–7. günleri ajanları kuruyor.

İş Öneri
Her sabah dünkü siparişlerin özetini e-postayla gönder Sabit akış

Ekibin Teams'ten “CAM-01 ne zaman gelir, montajı etkiler mi?” diye sorabildiği asistan Ajan (okuma araçlarıyla)

5. Maliyet ve hız (30 dk)

Her döngü adımı bir model çağrısıdır ve her çağrıda bütün geçmiş yeniden gönderilir. Beş adımlı bir ajan, tek bir sohbet sorusunun kabaca beş ila on katı token harcar ve birkaç saniyeden birkaç dakikaya kadar sürebilir. Bu yüzden:

  • Basit sınıflandırma ve bilgi çıkarma için küçük ve ucuz modeller genellikle yeterlidir; karmaşık planlama gerektiren ajanlarda daha güçlü model gerekir.
  • Model sağlayıcılarının panelinde aylık harcama sınırı koy.
  • n8n'de her çalıştırmanın kaç token harcadığını çalıştırma geçmişinde görürsün (4. gün).

Alıştırma: ajan.py'ye üçüncü bir araç ekle: stok(kod) (CAM-01 için 80 döndürsün). Sahte modele bir kural ekle: soruda “stok” geçiyorsa önce stok aracını çağırsın. “CAM-01 stokta kaç tane var?” sorusunu dene. Sonra en_cok_adim=1 yapıp ikinci soruyu tekrar çalıştır: ne oluyor?

GÜN 02

n8n'e giriş

~4 saat · 0/6 kontrol

Hedef

Gün sonunda n8n'i kurup editörünü tanıyacak; tetikleyici ve düğüm kavramlarını, düğümler arasında akan öğeleri (items) ve JSON veri modelini anlayacak; {{ }} ifadeleriyle bir öğenin alanlarını kullanacak; ilk iş akışını kurup çalıştıracak, çalıştırma geçmişini okuyacak ve iş akışlarını JSON olarak dışa ve içe aktarabileceksin. Süre yaklaşık 4 saat.

1. n8n nedir, nasıl kurulur? (45 dk)

n8n, uygulamaları ve servisleri birbirine bağlayan, görsel bir iş akışı otomasyonu aracıdır: “e-posta gelince → içinden bilgi çıkar → tabloya yaz → Teams'e bildir” gibi akışları kutucukları (düğümler) birleştirerek kurarsın. Benzerleri Zapier, Make ve Power Automate'tir. n8n'in farkları: kendi bilgisayarında ya da sunucunda ücretsiz çalıştırabilirsin (Community Edition), her düğümde JavaScript ya da Python kod yazabilirsin ve yapay zekâ düğümleri (dil modelleri, ajanlar, MCP) yerleşiktir.

Üç kurulum yolu:

Yol Komut / adım Ne zaman
Docker (önerilen) docker volume create n8n_data ve docker run -it --rm --name n8n -p 5678:5678 -v n8n_data:/home/node/.n8n docker.n8n.io/n8nio/n8n Kendi bilgisayarında kalıcı kurulum
npx npx n8n (Node.js 22 gerekir) Docker yoksa hızlı deneme

Kurulumdan sonra tarayıcıda http://localhost:5678 adresini aç, bir sahip (owner) hesabı oluştur. Docker komutundaki -v n8n_data:... kısmı iş akışlarının ve ayarların konteyner silinse de kaybolmamasını sağlar. Docker eğitimindeki birim (volume) kavramı burada işe yarıyor.

Kendi bilgisayarında çalışan n8n'in sınırı: Bilgisayarın kapanınca akışlar da durur. Her saat ya da her e-postada çalışması gereken akışlar için n8n bir sunucuda (şirket sunucusu, bulut sanal makinesi) ya da n8n Cloud'da çalışmalıdır. Kursu kendi bilgisayarında yapabilirsin.

2. Editör, tetikleyici ve düğümler (45 dk)

Yeni bir iş akışı oluşturduğunda boş bir tuval açılır. Temel kavramlar:

  • Tetikleyici (trigger): Akışı başlatan düğüm. Manual Trigger (“Execute workflow” düğmesine basınca), Schedule Trigger (zamanlanmış), Webhook (bir adrese istek gelince), Gmail/Outlook Trigger (yeni e-posta gelince), Chat Trigger (sohbet mesajı gelince).
  • Düğüm (node): Bir iş yapan kutu: veri değiştir, filtrele, bir servise istek gönder, e-posta at, dil modeli çağır.
  • Bağlantı: Bir düğümün çıktısının diğerine girdi olması.
  • Çalıştırma (execution): Akışın bir kez baştan sona çalışması. Her çalıştırma kaydedilir.

Bir akışın iki hâli vardır: test (editörde elle çalıştırırsın, her düğümün çıktısını görürsün) ve yayında (Publish/Active: tetikleyici kendiliğinden çalıştırır). Akışı yayına almadan önce mutlaka test et.

3. Öğeler ve JSON (45 dk)

n8n'de düğümler arasında öğe listeleri akar. Her öğe bir JSON nesnesidir; bir tablo satırı gibi düşünebilirsin:

[
  { "proje": "P-101", "kod": "cam-01", "adet": 120, "fiyat": 1450 },
  { "proje": "P-101", "kod": "slk-01", "adet": 60,  "fiyat": 310 },
  ...
]

Çoğu düğüm her öğe için bir kez çalışır: dört öğe gelirse “Edit Fields” düğümü dört kez çalışır, “Send Email” dört e-posta gönderir. Bu n8n'in en önemli kuralıdır ve başlangıçta en çok şaşırtan davranışıdır. Bütün öğeleri tek bir işlemde birleştirmek gerektiğinde (örneğin tek bir özet e-posta) Aggregate ya da Summarize düğümü kullanılır (yarın).

Düğümün çıktısını editörde üç görünümde inceleyebilirsin: Table, JSON ve Schema.

4. İfadeler (45 dk)

Bir düğümün alanına sabit bir değer yerine ifade (expression) yazabilirsin: {{ }} içindeki her şey JavaScript olarak, o anki öğe için hesaplanır.

İfade Anlamı {adet: 120, fiyat: 1450, kod: "cam-01"} için
{{ $json.adet }} Bu öğenin adet alanı 120
{{ $json.adet * $json.fiyat }} Hesap 174000
{{ $json.kod.toUpperCase() }} Metin işlemi CAM-01
{{ $json.adet > 100 ? "büyük" : "küçük" }} Koşul büyük
{{ $('Siparişler').item.json.proje }} Başka bir düğümdeki eşleşen öğe P-101
{{ $now.toFormat('dd.MM.yyyy') }} Şu anki tarih (Luxon) 17.11.2026

Editörde bir alana {{ yazınca ifade düzenleyicisi açılır; sol taraftaki önceki düğümlerin alanlarını sürükleyip bırakabilir, sağda sonucun önizlemesini görebilirsin. Önizlemeyi görmek için önceki düğümün bir kez çalışmış olması gerekir.

1. HTTP ile veri almak (45 dk)

Gerçek işlerde veri bir yerden gelir: bir web servisi (API), bir tablo, bir veritabanı. n8n'de yüzlerce hazır bağlantı düğümü vardır (Google Sheets, Microsoft Excel 365, Airtable, Postgres, Gmail, Outlook, Teams, Slack…); hazır düğümü olmayan her servis için HTTP Request düğümü kullanılır.

Bugün bir sipariş servisi yerine, bilgisayarında küçük bir web sunucusunun sunduğu bir JSON dosyası kullanacağız. Kurs dosyalarındaki siparisler.json altı sipariş içeriyor; dosyayı dünkü n8n_calistir.py ile aynı klasöre koy ve o klasörde bir terminal aç ve sunucuyu başlat (açık kalsın):

6. Hata yönetimi (30 dk)

Yayındaki bir akış gece 3'te hata verirse ne olacak? n8n'de üç katman:

  1. Düğüm ayarı: Her düğümün Settings sekmesinde Retry On Fail (örneğin 3 deneme, 5 saniye arayla) ve On Error (Stop Workflow / Continue / Continue using error output). Geçici ağ hatalarında yeniden deneme çoğu sorunu çözer.
  2. Hata çıkışı: “Continue (using error output)” seçilince düğüme ikinci bir çıkış eklenir; hatalı öğeler oraya gider ve ayrı işlenir (örneğin bir “hatalı kayıtlar” listesine yazılır).
  3. Error Workflow: Akışın ayarlarında (Settings → Error Workflow) bir hata akışı seçilir. Bu akış Error Trigger ile başlar ve hangi akışın hangi düğümde hata verdiği bilgisini alır; sana e-posta ya da Teams mesajı atar. Her yayındaki akışa bir hata akışı bağlamak iyi bir alışkanlıktır.

Alıştırma: akis3.json'u değiştir: (1) Switch'e üçüncü bir kol ekle: durumu “yeni” olan ve teslimine 7 günden az kalan siparişler ($now ile karşılaştır). (2) Tek mesaj düğümünün yerine Aggregate düğümü kullanmayı dene. (3) HTTP Request düğümünün URL'sini bilerek bozup akışı çalıştır, hatayı Executions'ta incele; sonra Retry On Fail'i aç.

GÜN 05

AI Agent düğümü

~4 saat · 0/6 kontrol

Hedef

Gün sonunda n8n'in AI Agent düğümünü bir model ve araçlarla kuracak; iyi bir sistem mesajı ve iyi bir araç açıklaması yazacak; Code, HTTP Request ve alt iş akışı araçlarını bilecek; sohbet tetikleyicisi ve bellekle konuşan bir asistan kuracak; adım sınırını ayarlayacak ve ajanı bir soru listesiyle test edebileceksin. Süre yaklaşık 4,5 saat.

1. AI Agent düğümü (30 dk)

  1. günde Python'da yazdığımız döngünün n8n'deki karşılığı AI Agent düğümüdür. Altına üç tür alt düğüm bağlanır:
  • Chat Model (zorunlu): kararı veren model. Ajanlarda araç çağırmayı iyi yapan bir model seç; çok küçük modeller aracı yanlış seçebilir ya da hiç çağırmayabilir.
  • Memory (isteğe bağlı): konuşma geçmişi.
  • Tool (bir ya da daha çok): modelin çağırabileceği araçlar.

Düğümün ayarları: Prompt (kullanıcının mesajı; sohbet tetikleyicisinden otomatik gelir ya da bir ifadeyle tanımlanır), System Message (rol ve kurallar), Max Iterations (en çok döngü adımı, varsayılan 10).

2. Sistem mesajı (45 dk)

Sistem mesajı ajanın “iş tanımı”dır. İyi bir sistem mesajı dört şey söyler:

  1. Rol ve görev: “Sen bir cephe firmasının satın alma asistanısın. Görevin sipariş durumunu yanıtlamak.”
  2. Araç kuralları: “Sipariş bilgisini SADECE siparis_durumu aracından al, asla tahmin etme.”
  3. Sınırlar ve hata davranışı: “Araç hata döndürürse bunu açıkça söyle.” “Sipariş vermek, iptal etmek gibi işlemleri yapamazsın; kullanıcıyı satın alma sorumlusuna yönlendir.”
  4. Biçim: “Yanıtların kısa ve Türkçe olsun. Tarihleri GG.AA.YYYY yaz.”

Kaçınılacaklar: çok uzun, birbiriyle çelişen kurallar; “her zaman”, “asla” ifadelerinin aşırı kullanımı; bilinmeyen durumlar için davranış tanımlamamak.

3. Araçlar ve açıklamaları (1 saat)

Model hangi aracı ne zaman çağıracağına araç adı, açıklaması ve girdi şemasına bakarak karar verir. Bu üçü, ajanın kalitesini sistem mesajı kadar belirler.

GÜN 06

MCP ve güvenlik

~4 saat · 0/6 kontrol

Hedef

Gün sonunda Model Context Protocol'ün (MCP) ne olduğunu ve neden önemli olduğunu bilecek; n8n'de bir MCP sunucusunun araçlarını ajana bağlayacak ve kendi n8n akışlarını MCP ile başka yapay zekâ araçlarına açacak; istem enjeksiyonunu bir benzetimle görecek ve en az yetki, insan onayı, kayıt ve izleme ile ajanları güvenli hâle getirebileceksin. Süre yaklaşık 4,5 saat.

1. MCP nedir? (45 dk)

Bir ajanın araçları şimdiye kadar n8n'in içindeydi. Peki aynı “sipariş durumu” aracını Claude Desktop'tan, VS Code'daki bir kod asistanından ya da başka bir ajandan da kullanmak istersen? Her biri için ayrı entegrasyon yazmak yerine ortak bir dil var: Model Context Protocol (MCP).

MCP, Anthropic'in 2024 sonunda yayınladığı ve kısa sürede bütün büyük yapay zekâ araçlarının benimsediği açık bir standarttır: yapay zekâ uygulamaları (istemci) ile araç ve veri sağlayan servisler (sunucu) arasında ortak bir arayüz. USB'ye benzetilir: bir kez MCP sunucusu yazarsın, her MCP istemcisi onu takıp kullanabilir.

Kavram Ne
MCP sunucusu Araçlar (tools), kaynaklar (resources) ve hazır istemler (prompts) sunan servis. Örnek: dosya sistemi, GitHub, veritabanı, senin n8n akışların
MCP istemcisi Sunucuya bağlanıp araçlarını modele veren uygulama: Claude Desktop, ChatGPT, Cursor, VS Code, n8n'in AI Agent'ı
Taşıma (transport) Yerel sunucular için standart giriş/çıkış (stdio), uzaktakiler için HTTP (Streamable HTTP; eski sürümlerde SSE)

n8n MCP'yi iki yönde de kullanır:

  • MCP Client Tool düğümü: Bir MCP sunucusunun araçlarını AI Agent'a bağlar. Sunucunun URL'sini ve gerekiyorsa kimlik bilgisini verirsin, hangi araçların ajana açılacağını seçersin (hepsi ya da seçilenler).
  • MCP Server Trigger düğümü: Senin n8n araçlarını (Code Tool, Workflow Tool, Google Sheets Tool…) bir MCP sunucusu olarak yayınlar. Düğüm bir URL verir; bu URL Claude Desktop gibi bir istemciye eklenince, oradaki model senin akışlarını araç olarak çağırabilir. n8n 2.x'te ayrıca bütün örneği (instance) MCP sunucusu olarak açan bir ayar da vardır.

2. n8n akışını MCP sunucusu yapmak (1 saat)

Dünkü siparis_durumu aracını bir MCP sunucusu olarak yayınlayalım:

  1. Yeni bir akış: MCP Server Trigger düğümü ekle. Kimlik doğrulama için Bearer Auth ya da Header Auth seç; açık bırakma.
  2. Trigger'ın altındaki Tool girişine dünkü siparis_durumu Code Tool'unu (kopyala-yapıştır) bağla. Gerekirse daha fazla araç ekle.
  3. Akışı yayına al (Publish). Trigger düğümünde Production URL görünür, örneğin https://n8n.sirketim.com/mcp/siparis/....
  4. İstemci tarafında (örneğin Claude Desktop ya da başka bir MCP destekli uygulamada) “uzak MCP sunucusu ekle” bölümüne bu URL'yi ve token'ı gir. Bazı istemciler sadece yerel (stdio) sunucuları destekler; onlar için mcp-remote gibi bir köprü paketi kullanılır. İstemcinin güncel belgesine bak.

Artık istemcide “CAM-01 ne durumda?” diye sorduğunda model senin n8n aracını çağırır. Aynı araç n8n içindeki ajanlar, şirketin sohbet asistanı ve geliştiricilerin kod asistanları tarafından ortak kullanılır; mantık tek yerde kalır.

Tersi yön için: AI Agent'a MCP Client Tool ekle, başka bir MCP sunucusunun URL'sini ver. Örneğin şirketin belge yönetim sisteminin MCP sunucusunu bağlayıp ajana “şartnamede ara” aracını kazandırabilirsin. Yalnızca güvendiğin sunucuları bağla: bir MCP sunucusunun araç açıklamaları da modele giden metindir ve kötü niyetli talimat içerebilir.

3. İstem enjeksiyonu (1 saat)

Ajanın okuduğu her metin (e-posta, web sayfası, belge, araç sonucu) modelin bağlamına girer. Model, sistem mesajındaki talimat ile verinin içine gizlenmiş talimatı her zaman ayırt edemez. Buna istem enjeksiyonu (prompt injection) denir ve ajanların en ciddi güvenlik sorunudur.

Benzetim: tedarikçi e-postalarını okuyup gerekirse sipariş güncelleyen bir ajan. E-postalardan biri saldırgan:

import re

SIPARISLER = {"CAM-01": "üretimde", "SLK-01": "teslim edildi", "ANK-01": "yeni"}
KAYIT = []


def siparis_oku(kod):
    return SIPARISLER.get(kod, "yok")


def siparis_iptal(kod):
    SIPARISLER[kod] = "İPTAL"
    return f"{kod} iptal edildi"


def saf_model(metin):
    """Metinde ne yazıyorsa onu yapmaya çalışan bir model benzetimi."""
    istekler = []
    for kod in re.findall(r"[A-Z]{3}-\d{2}", metin):
        islem = "siparis_iptal" if re.search(r"iptal", metin, re.I) else "siparis_oku"
        istekler.append((islem, kod))
    return istekler


def calistir(eposta, araclar, onay_gereken=()):
    for islem, kod in saf_model(eposta):
        if islem not in araclar:
            KAYIT.append(f"ENGELLENDİ: {islem}({kod}) bu ajana verilmemiş")
            continue
        if islem in onay_gereken:
            KAYIT.append(f"ONAY BEKLİYOR: {islem}({kod})")
            continue
        KAYIT.append(f"{islem}({kod}) -> {araclar[islem](kod)}")

5. Yayına almak (45 dk)

Denemeden gerçeğe geçerken değiştirilecekler:

  1. Tetikleyici: “Başlat” ve “E-postalar” düğümlerini Microsoft Outlook Trigger (ya da Gmail Trigger) ile değiştir; sadece satın alma kutusunu, belirli klasörü ve okunmamışları dinlesin. İfadelerdeki $json.metin alanını tetikleyicinin gövde alanına göre düzelt (örneğin $json.body.content).
  2. Sipariş servisi: HTTP Request'i şirketin gerçek servisine ya da Google Sheets / Microsoft Excel 365 düğümünün “Update Row” işlemine çevir.
  3. Bildirimler: Code/Set düğümlerinin ardına Microsoft Teams ya da Outlook Send düğümü ekle.
  4. İnsana sor: Outlook / Gmail / Teams → Send and Wait for Response ile satın alma sorumlusuna e-postayı ve “kod ve tarihi girin” formunu gönder; yanıt gelince aynı güncelleme koluna bağla.
  5. Model: Sahte model kimlik bilgisini gerçek sağlayıcınınkiyle değiştir; harcama sınırını koy.
  6. Hata akışı: Akışın ayarlarında bir Error Workflow seç (3. gün).
  7. Gölge mod: İlk hafta “Siparişi güncelle” yerine sadece bir kayıt tablosuna yaz; akışın kararlarını satın alma ekibinin elle yaptıklarıyla karşılaştır. Doğruluk yeterliyse güncellemeyi aç.
