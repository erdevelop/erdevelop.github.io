GÜN 01

Docker nedir?

~4 saat · 0/6 kontrol

Hedef

Gün sonunda Docker'ın hangi sorunu çözdüğünü, kapsayıcının sanal makineden farkını ve imaj, kapsayıcı, kayıt kavramlarını bilecek; Docker'ı kurup ilk kapsayıcını çalıştırmış olacaksın. Süre yaklaşık 4 saat.

Bu kurs hakkında: Örneklerde Python ile yazılmış küçük programlar kullanılır, ama Docker dilden bağımsızdır: Node.js, Java, Go ya da bir veritabanı da aynı şekilde kapsayıcıya konur. Komutlar Windows (PowerShell), macOS ve Linux'ta aynıdır.

1. Hangi sorunu çözer? (30 dk)

Bir Python programını arkadaşına gönderdin. Onun bilgisayarında çalışmıyor: Python sürümü farklı, bir kütüphane eksik, başka bir programın istediği sürümle çakışıyor. Sunucuya kurarken de aynı sorunlar çıkıyor. Klasik çözüm, uzun bir "kurulum adımları" belgesidir ve her seferinde bir şey eksik kalır.

Docker, programı çalışması için gereken her şeyle (işletim sistemi dosyaları, dil sürümü, kütüphaneler, ayarlar) birlikte tek bir pakete koyar. Bu pakete imaj denir. İmajı Docker kurulu her bilgisayarda aynı şekilde çalıştırırsın; çalışan hâline kapsayıcı (container) denir.

Benzetme: Gemilerdeki standart konteynerler gibi. İçinde ne olduğu önemli değil (muz, otomobil, kumaş); vinç, gemi ve kamyon onu hep aynı biçimde taşır. Docker da içindeki program ne olursa olsun kapsayıcıyı aynı komutlarla çalıştırır, durdurur ve taşır.

2. Kapsayıcı ve sanal makine (30 dk)

Bir sanal makine (VirtualBox, VMware, Hyper-V) donanımı taklit eder ve içinde tam bir işletim sistemi çekirdeğiyle birlikte çalışır. Ağırdır: gigabaytlarca yer kaplar, açılması dakikalar sürer.

Bir kapsayıcı ise kendi çekirdeğini getirmez; bilgisayarın Linux çekirdeğini paylaşır. Sadece programı ve onun ihtiyaç duyduğu dosyaları içerir. Çekirdek, kapsayıcıları birbirinden ve bilgisayardan yalıtır: her kapsayıcı kendi dosya sistemini, süreçlerini ve ağını görür.

Kapsayıcılar Linux çekirdeğinin özelliklerine dayanır. Windows ve macOS'ta Docker Desktop, arka planda küçük bir Linux sanal makinesi (Windows'ta WSL 2) çalıştırır ve kapsayıcıları onun içinde başlatır; sen bunu fark etmezsin.

3. Üç kavram: imaj, kapsayıcı, kayıt (45 dk)

  • İmaj (image): Programın ve ihtiyaçlarının salt okunur bir kalıbı. Bir tarif ya da bir sınıf (class) gibidir. Adı ad:etiket biçimindedir: python:3.12-slim, postgres:17, nginx:latest. Etiket verilmezse latest varsayılır.
  • Kapsayıcı (container): İmajdan başlatılan çalışan bir örnek. Aynı imajdan istediğin kadar kapsayıcı başlatabilirsin; her birinin kendi yazılabilir alanı vardır. Tariften pişirilmiş yemek ya da sınıftan oluşturulmuş nesne gibidir.
  • Kayıt (registry): İmajların saklandığı depo. En bilineni Docker Hub'dır (hub.docker.com); GitHub Container Registry (ghcr.io) ve bulut sağlayıcılarının kayıtları da yaygındır. docker pull indirir, docker push gönderir.

İmajı sen de yazabilirsin: bir Dockerfile ("şu imajdan başla, şu dosyaları kopyala, şu komutu çalıştır") yazıp docker build ile imaj üretirsin. Bunu 3. günde yapacağız.

Resmî imajlar: Docker Hub'da python, node, postgres, nginx gibi adların başında kullanıcı adı olmayan imajlar resmî imajlardır ve güvenle kullanılabilir. birisi/imaj-adi biçimindekiler kişi ya da kurumlara aittir; kaynağını bilmediğin imajları kullanma.

4. Kurulum (45 dk)

  1. Windows: Önce WSL'yi kur (yönetici PowerShell'de wsl --install), sonra docker.com'dan Docker Desktop'ı indirip kur. Kurulumda "Use WSL 2" seçeneği işaretli olsun. Bilgisayarı yeniden başlat ve Docker Desktop'ı aç; sol altta motorun çalıştığını gösteren yeşil bir işaret görünür.
  2. macOS: Docker Desktop'ı indir (Apple Silicon ya da Intel sürümünü seç) ve Uygulamalar'a sürükle.
  3. Linux (Ubuntu): Docker'ın belgesindeki depo kurulumunu izle, ardından kullanıcını docker grubuna ekle ki her komutta sudo gerekmesin:
sudo usermod -aG docker $USER
newgrp docker

Kurulumu terminalde doğrula:

docker version
docker run hello-world

docker version hem istemcinin (Client) hem motorun (Server) sürümünü yazmalıdır; sadece Client görünüyorsa Docker Desktop açık değildir. hello-world imajı küçük bir test programıdır: indirilir, çalışır ve "Hello from Docker!" ile başlayan, az önce olanları adım adım anlatan bir mesaj yazar.

5. İlk kapsayıcı (1 saat)

docker run imaj komut imajdan yeni bir kapsayıcı oluşturur, içinde komutu çalıştırır ve komut bitince kapsayıcı durur. İmaj bilgisayarda yoksa önce kayıttan indirilir (ilk seferde biraz sürer, sonra önbellekten gelir).

docker run --rm python:3.12-slim python -c "print('Merhaba kapsayıcıdan!')"

Merhaba kapsayıcıdan!

--rm kapsayıcıyı iş bitince siler; denemelerde ortalığı temiz tutar. Bilgisayarında Python kurulu olmasa bile bu komut çalışır: Python, imajın içindedir.

Kapsayıcının kendi dünyasını gördüğünü kontrol edelim:

docker run --rm python:3.12-slim bash -c 'whoami; pwd; ls /; echo "süreç sayısı: $(ls /proc | grep -c "^[0-9]")"'

Çıktıda kapsayıcının root kullanıcısıyla çalıştığını, kendi kök dosya sistemini (/bin, /etc, /usr…) gördüğünü ve içinde sadece birkaç süreç olduğunu görürsün: bilgisayarındaki yüzlerce süreç kapsayıcıdan görünmez. Kapsayıcıdaki root, varsayılan olarak bilgisayarındaki dosyalara erişemez; 7. günde imajları root olmayan bir kullanıcıyla çalıştırmayı da göreceğiz.

Yalıtım denemesi: Bir kapsayıcıda dosya oluşturup başka bir kapsayıcıda arayalım:

docker run --rm python:3.12-slim bash -c 'echo deneme > /tmp/not.txt && cat /tmp/not.txt'
docker run --rm python:3.12-slim bash -c 'cat /tmp/not.txt 2>&1 || true'

deneme
cat: /tmp/not.txt: No such file or directory

İkinci kapsayıcı aynı imajdan yepyeni başladı; ilkinin yaptığı değişikliği görmez. Her kapsayıcı imajın temiz bir kopyasıyla başlar. Bu, Docker'ın en önemli özelliğidir: her çalıştırma tekrarlanabilir. Kalıcı veri saklamanın yolunu 4. günde göreceğiz.

İndirilmiş imajları docker images (ya da docker image ls) listeler; ad, etiket, kimlik ve boyut gösterir.

docker images --format '{{.Repository}}:{{.Tag}}' | grep python

python:3.12-slim

--format çıktıyı istediğin sütunlarla sınırlar; betiklerde çok kullanılır.

Alıştırma: python:3.12-slim imajında bir kapsayıcı çalıştırıp içinde python -c "import sys; print(sys.version)" komutuyla Python sürümünü yazdır. Sonra aynı imajla cat /etc/os-release çalıştırıp kapsayıcının hangi Linux dağıtımına dayandığına bak.

GÜN 02

Kapsayıcıları yönetmek

~4 saat · 0/6 kontrol

Hedef

Gün sonunda kapsayıcıları etkileşimli ya da arka planda çalıştırabilecek, adlandırıp listeleyebilecek, günlüklerini okuyup içine girebilecek; port yayınlayıp ortam değişkeni geçebilecek ve işin bitince durdurup silebileceksin. Süre yaklaşık 4 saat.

1. Kapsayıcının yaşam döngüsü (30 dk)

Bir kapsayıcı şu durumlardan geçer: oluşturuldu (created), çalışıyor (running), durdu (exited) ve silindi. docker run aslında üç işi birden yapar: imajı gerekirse indirir (pull), kapsayıcıyı oluşturur (create) ve başlatır (start).

Duran bir kapsayıcı silinmediği sürece diskte kalır; docker start ile yeniden başlatılabilir ve içindeki değişiklikler korunur. --rm verirsen durduğu anda silinir.

Komut Ne yapar
docker ps Çalışan kapsayıcılar
docker ps -a Duranlar dahil hepsi
docker stop ad Durdurur (önce SIGTERM, 10 sn sonra SIGKILL)
docker start ad Duranı yeniden başlatır
docker restart ad Durdurup başlatır
docker rm ad Duranı siler (-f çalışanı da zorla siler)
docker container prune Bütün duran kapsayıcıları siler

2. Etkileşimli kapsayıcı: -it (30 dk)

-i (interactive) girdiyi açık tutar, -t (tty) bir terminal ayırır. Birlikte, kapsayıcının içinde bir kabuk açmanı sağlar:

docker run -it --rm python:3.12-slim bash

İstem root@3f2a9c1b7d4e:/# gibi bir şeye döner; @'ten sonraki kapsayıcının kimliğidir. İçeride istediğin komutu dene, exit yazınca kabuk biter ve kapsayıcı durur (--rm olduğu için silinir). Etkileşimli Python için sondaki bash yerine python yaz.

3. Arka planda çalıştırmak: -d ve --name (45 dk)

Web sunucusu gibi sürekli çalışan programlar -d (detached) ile arka planda başlatılır. --name kapsayıcıya hatırlanabilir bir ad verir; vermezsen Docker heuristic_curie gibi rastgele bir ad koyar.

Python'un yerleşik web sunucusunu bir kapsayıcıda başlatalım:

docker run -d --name web python:3.12-slim python -m http.server 8000 > /dev/null
docker ps --format '{{.Names}}  {{.Image}}  {{.Command}}'

web  python:3.12-slim  "python -m http.serv…"

docker run -d başlattığı kapsayıcının uzun kimliğini yazar; burada > /dev/null ile gizledik. docker ps normalde kimlik, imaj, komut, oluşturulma zamanı, durum, portlar ve ad sütunlarını gösterir.

4. Port yayınlamak: -p (45 dk)

Kapsayıcının içindeki sunucu 8000 portunu dinliyor, ama bu port kapsayıcının kendi ağındadır; bilgisayarından ulaşamazsın. -p bilgisayar_portu:kapsayıcı_portu ile bir portu dışarı yayınlarsın:

docker rm -f web > /dev/null
mkdir -p site && echo "<h1>Kule A şantiye sayfası</h1>" > site/index.html
docker run -d --name web -p 8080:8000 -v "$PWD/site:/site" -w /site python:3.12-slim python -m http.server 8000 > /dev/null
sleep 1
curl -s http://localhost:8080/
docker port web

<h1>Kule A şantiye sayfası</h1>
8000/tcp -> 0.0.0.0:8080

Artık tarayıcıda http://localhost:8080 adresine gidersen sayfayı görürsün. İki yeni seçenek de kullandık; ikisini de ilerleyen günlerde ayrıntılı göreceğiz:

  • -v "$PWD/site:/site" bilgisayarındaki site klasörünü kapsayıcının içinde /site olarak gösterir (bind mount, 4. gün). Windows PowerShell'de $PWD yerine ${PWD} yazılır.
  • -w /site kapsayıcıdaki çalışma klasörünü belirler.

Bilgisayar portu boşta olmalıdır: aynı anda iki kapsayıcı -p 8080:... kullanamaz. Kapsayıcı tarafı ise her kapsayıcıda aynı olabilir. Örneğin -p 8081:8000 ile ikinci bir kopyayı başka porttan yayınlayabilirsin.

5. Günlükler ve içine girmek: logs ve exec (45 dk)

Bir kapsayıcının ekrana (stdout ve stderr) yazdığı her şey Docker tarafından saklanır. docker logs bunları gösterir:

curl -s -o /dev/null http://localhost:8080/olmayan.html
docker logs web 2>&1 | grep -c "GET"
docker logs web 2>&1 | grep -o '"GET [^"]*" [0-9]*'

2
"GET / HTTP/1.1" 200
"GET /olmayan.html HTTP/1.1" 404

docker logs -f web günlüğü canlı izler (Ctrl+C ile çıkılır), --tail 20 son 20 satırı, --since 10m son 10 dakikayı gösterir. Kapsayıcıda çalışan programlar günlükleri dosyaya değil ekrana yazmalıdır; Docker'ın günlük sistemi buna göre tasarlanmıştır.

docker exec çalışan bir kapsayıcının içinde ek bir komut çalıştırır. Hata ayıklamanın en önemli aracıdır:

docker exec web ls /site
docker exec web python -c "import os; print(os.getcwd())"

index.html
/site

İçeride bir kabuk açmak için docker exec -it web bash kullanılır. run yeni bir kapsayıcı başlatır; exec var olana girer. Bu farkı karıştırmamak önemlidir.

6. Ortam değişkenleri: -e (30 dk)

Programın ayarlarını (veritabanı adresi, dil, hata ayıklama modu) imajın içine yazmak yerine ortam değişkeniyle dışarıdan vermek Docker'ın temel kurallarından biridir. Böylece aynı imaj geliştirme, test ve canlı ortamda farklı ayarlarla çalışır.

docker run --rm -e PROJE="Kule B" -e KAT=24 python:3.12-slim \
  python -c "import os; print(os.environ['PROJE'], '-', os.environ['KAT'], 'kat')"

Kule B - 24 kat

Çok sayıda değişken için bir dosya kullanılır: her satırda AD=değer olan bir .env dosyası yazıp --env-file .env ile verirsin. Parola gibi gizli değerleri içeren .env dosyalarını Git'e ekleme.

7. Durdurmak, silmek, temizlik (30 dk)

docker stop web > /dev/null
docker ps --format '{{.Names}}' | grep -c web || true
docker ps -a --filter name=web --format '{{.Names}}: {{.State}}'
docker rm web

0
web: exited
web

docker stop kapsayıcıyı durdurdu ama silmedi (ps -a'da exited görünüyor); docker rm sildi ve adını yazdı.

Zamanla diskte kullanılmayan kapsayıcı ve imajlar birikir. Ne kadar yer kapladıklarını docker system df gösterir; temizlik için:

docker container prune   # duran bütün kapsayıcılar
docker image prune       # etiketsiz (dangling) imajlar
docker system prune      # hepsi: duran kapsayıcılar, kullanılmayan ağlar, dangling imajlar, önbellek

Hepsi silmeden önce onay ister. docker system prune -a kullanılmayan bütün imajları da siler; sonra hepsi yeniden indirilir.

Kaynak sınırı: Bir kapsayıcının bütün belleği yemesini önlemek için --memory 512m ve --cpus 1.5 gibi sınırlar verilebilir. docker stats çalışan kapsayıcıların CPU ve bellek kullanımını canlı gösterir.

Alıştırma: python:3.12-slim ile iki web sunucusu başlat: site1 adlısı 8081, site2 adlısı 8082 portundan yayınlansın ve farklı birer index.html göstersin. curl ile ikisini de dene, docker logs ile isteklerin geldiğini gör, docker exec ile site1'in içinde yeni bir dosya oluşturup tarayıcıdan aç. Son olarak tek komutla ikisini birden sil: docker rm -f site1 site2.

GÜN 03

Dockerfile yazmak

~4 saat · 0/6 kontrol

Hedef

Gün sonunda kendi programın için bir Dockerfile yazıp docker build ile imaj üretebilecek, imajı etiketleyip çalıştırabilecek; katmanların ve build önbelleğinin nasıl çalıştığını anlayıp Dockerfile'ı hızlı build edilecek şekilde sıralayabileceksin. Süre yaklaşık 4 saat.

1. Uygulama (30 dk)

Kapsayıcıya koyacağımız program, cephe panellerinin listesini JSON olarak veren küçük bir web servisi. Python'un popüler web kütüphanesi Flask ile yazıldı. Bir klasör oluştur ve içine üç dosya koy.

mkdir -p panel-api && cd panel-api

app.py

import os
from flask import Flask, jsonify

app = Flask(__name__)
PANELLER = [
    {"kod": "P-101", "kat": 3, "en": 1500, "boy": 3200, "durum": "montaj"},
    {"kod": "P-102", "kat": 3, "en": 1500, "boy": 3200, "durum": "üretim"},
    {"kod": "P-201", "kat": 4, "en": 1200, "boy": 3200, "durum": "tasarım"},
]


@app.get("/")
def ana():
    return jsonify(proje=os.environ.get("PROJE", "tanımsız"), panel_sayisi=len(PANELLER))


@app.get("/paneller")
def paneller():
    return jsonify(PANELLER)


if __name__ == "__main__":
    app.run(host="0.0.0.0", port=8000)

host="0.0.0.0" önemlidir: Flask varsayılan olarak sadece 127.0.0.1'i dinler ve kapsayıcının içinden dışarıya kapalı kalır. Kapsayıcıda çalışan sunucular bütün arayüzleri dinlemelidir.

requirements.txt (kütüphaneler ve sürümleri)

flask==3.1.1

2. Dockerfile (1 saat)

Dockerfile (uzantısız, büyük D ile) imajın nasıl kurulacağını adım adım anlatan metin dosyasıdır. Her satır bir talimat ve argümanlarıdır:

# 1. Temel imaj: içinde Python 3.12 olan küçük bir Linux
FROM python:3.12-slim

# 2. Kapsayıcıdaki çalışma klasörü (yoksa oluşturulur)
WORKDIR /app

# 3. Önce sadece bağımlılık listesini kopyala ve kur
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# 4. Sonra uygulama kodunu kopyala
COPY app.py .

# 5. Varsayılan ayarlar ve belgeleme
ENV PROJE="Kule A"
EXPOSE 8000

# 6. Kapsayıcı başlayınca çalışacak komut
CMD ["python", "app.py"]
Talimat Ne yapar
FROM Hangi imajın üzerine kurulacağı. Her Dockerfile bununla başlar.
WORKDIR Sonraki komutların çalışacağı klasör. cd yerine kullanılır.
COPY kaynak hedef Bilgisayardaki dosyaları imaja kopyalar. . WORKDIR demektir.
RUN komut Build sırasında komut çalıştırır (paket kurmak gibi). Sonucu imaja kaydedilir.
ENV AD=değer Ortam değişkeni; docker run -e ile ezilebilir.
EXPOSE Programın hangi portu dinlediğini belgeler. Portu kendisi yayınlamaz; yine -p gerekir.
CMD [...] Kapsayıcı başlayınca çalışacak varsayılan komut. docker run imaj başka-komut ile ezilebilir.

Önbellek: Docker build sırasında her talimatı önceki build'le karşılaştırır. Talimat ve kopyalanan dosyalar değişmemişse katmanı yeniden üretmez, önbellekten kullanır (CACHED). Ama bir katman değişirse ondan sonraki bütün katmanlar yeniden üretilir.

Sadece app.py'yi değiştirip yeniden build edelim ve hangi adımların önbellekten geldiğine bakalım:

docker build --progress=plain -t panel-api:1.1 . 2>&1 \
  | awk '/^#[0-9]+ \[[2-5]\/5\]/ { ad[$1] = $2 " " $3 " " $4 }
         /^#[0-9]+ CACHED/ { onb[$1] = 1 }
         END { for (k in ad) print ad[k], (k in onb ? "→ önbellekten" : "→ yeniden üretildi") }' | sort

[2/5] WORKDIR /app → önbellekten
[3/5] COPY requirements.txt → önbellekten
[4/5] RUN pip → önbellekten
[5/5] COPY app.py → yeniden üretildi

Build çıktısında her adımın bir numarası (#5 gibi) vardır ve önbellekten gelen adımların altında CACHED yazar; awk ile bunları eşleştirip özetledik. Kendi denemende awk kısmını yazmadan çıktının tamamına bakabilirsin.

import os
import sqlite3
import sys

yol = os.environ.get("VERI_YOLU", "/veri/siparis.db")
os.makedirs(os.path.dirname(yol), exist_ok=True)
db = sqlite3.connect(yol)
db.execute("CREATE TABLE IF NOT EXISTS siparis (id INTEGER PRIMARY KEY, malzeme TEXT, adet INTEGER)")
malzeme = sys.argv[1] if len(sys.argv) > 1 else "Isıcam"
adet = int(sys.argv[2]) if len(sys.argv) > 2 else 1
db.execute("INSERT INTO siparis (malzeme, adet) VALUES (?, ?)", (malzeme, adet))
db.commit()
toplam = db.execute("SELECT COUNT(*), COALESCE(SUM(adet), 0) FROM siparis").fetchone()
print(f"eklendi: {malzeme} x{adet} | kayıt: {toplam[0]}, toplam adet: {toplam[1]}")

from http.server import BaseHTTPRequestHandler, HTTPServer


class Isleyici(BaseHTTPRequestHandler):

import json
import os
import sqlite3
from http.server import BaseHTTPRequestHandler, ThreadingHTTPServer

DB = os.environ.get("VERI_YOLU", "/veri/siparis.db")


def baglan():
    db = sqlite3.connect(DB)
    db.execute("""CREATE TABLE IF NOT EXISTS siparis (
        id INTEGER PRIMARY KEY, proje TEXT NOT NULL, malzeme TEXT NOT NULL,
        adet INTEGER NOT NULL, birim_fiyat REAL NOT NULL)""")
    return db


class Isleyici(BaseHTTPRequestHandler):
    def cevap(self, kod, veri):
        govde = json.dumps(veri, ensure_ascii=False).encode()
        self.send_response(kod)
        self.send_header("Content-Type", "application/json; charset=utf-8")
        self.end_headers()
        self.wfile.write(govde)

    def do_GET(self):
        if self.path == "/saglik":
            baglan().execute("SELECT 1")
            return self.cevap(200, {"durum": "iyi"})
        if self.path == "/siparisler":
            satirlar = baglan().execute("SELECT id, proje, malzeme, adet, birim_fiyat FROM siparis").fetchall()
            ad = ["id", "proje", "malzeme", "adet", "birim_fiyat"]
            return self.cevap(200, [dict(zip(ad, s)) for s in satirlar])
        self.cevap(404, {"hata": "bulunamadı"})

    def do_POST(self):
        if self.path != "/siparisler":
            return self.cevap(404, {"hata": "bulunamadı"})
        try:
            s = json.loads(self.rfile.read(int(self.headers["Content-Length"])))
            alanlar = (s["proje"], s["malzeme"], int(s["adet"]), float(s["birim_fiyat"]))
        except (KeyError, ValueError, TypeError):
            return self.cevap(400, {"hata": "proje, malzeme, adet ve birim_fiyat gerekli"})
        with baglan() as db:
            yeni = db.execute("INSERT INTO siparis (proje, malzeme, adet, birim_fiyat) VALUES (?, ?, ?, ?)", alanlar).lastrowid
        self.cevap(201, {"id": yeni})

    def log_message(self, bicim, *args):
        print(f"{self.command} {self.path} -> {args[1] if len(args) > 1 else ''}", flush=True)


if __name__ == "__main__":
    print("api 8000 portunda", flush=True)
    ThreadingHTTPServer(("0.0.0.0", 8000), Isleyici).serve_forever()

def rapor_uret():

6. Sonraki adımlar (15 dk)

  • Gerçek veritabanı: SQLite tek bir uygulama için harikadır. Birden çok servis aynı veriye yazacaksa Compose'a bir postgres:17 servisi ekle; resmi imaj POSTGRES_PASSWORD ve POSTGRES_DB ortam değişkenleriyle ayarlanır, verisini /var/lib/postgresql/data altına bir volume ile saklarsın. (Bu kursun hazırlandığı ortamda Docker Hub'a erişim olmadığı için PostgreSQL örneği çalıştırılmadı.)
  • Ters vekil ve HTTPS: Birden çok servisi tek bir alan adının altında yayınlamak için önde nginx, Caddy ya da Traefik kullanılır.
  • CI/CD: GitHub Actions ile her git push'ta imajı build edip test eden ve kayda gönderen bir iş akışı kur.
  • Kubernetes: Yüzlerce kapsayıcıyı birden çok sunucuda yönetmek gerektiğinde bir sonraki adımdır; Compose'da öğrendiğin servis, ağ, volume ve sağlık kontrolü kavramları orada da aynen geçerlidir.
  • Veri ve ML projeleri: Python ile veri analizi ve Makine öğrenmesine giriş eğitimlerindeki betikleri ve modelleri bu kursta öğrendiğin şekilde imaja koyup her bilgisayarda aynı sonucu alabilirsin.
