Creating Revit Families

Learn to build parametric Revit families in 7 days with facade examples: skeleton, parameters, forms, formulas, nested families, arrays, panel families, and from testing to the library.

Before you start

Who is it for

Facade designers and BIM modellers who know the Revit basics and want to make their own bracket, panel and profile families.

What you need

  • Revit (screenshots are from the 2027 English interface)
  • Basic Revit knowledge (Revit Step by Step, in Turkish)
  • An empty test project

DAY 01

Family types and the editor

~3.5 h · 0/5 checks

Goal

By the end of the day you will know the family types in Revit, how to choose the right template, the parts of the Family Editor and the family category. About 3 hours.

About this course: The screenshots are from the Revit® 2027 English interface; locations may differ slightly in older versions. If you are new to Revit, start with the Revit Step by Step course (in Turkish). How families are used in facade projects is covered in Revit in 30 Days (in Turkish); this course focuses on building families. Terms are explained in the glossary.

1. Family types (30 min)

Type Where Example
System family Inside the project; no file, duplicated by copying the type Wall, floor, curtain wall, roof
Loadable family Separate .rfa file loaded into the project Door, window, panel, bracket, profile
In-place family Inside the project, one-off A special canopy, a single sculpture

Loadable families dominate in facades: curtain wall panels, mullion profiles, anchor brackets, louvres. Use in-place families only for things that will be used once and never repeat; they are weak for schedules and copying.

2. New family and template (45 min)

  1. File > New > Family.
  2. Choose a template (.rft). The template sets the family's category, its host and the starting planes.
Template For
Metric Generic Model General purpose, unhosted family
Metric Generic Model face based Placed on a face (bracket, anchor plate)
Metric Curtain Wall Panel Curtain wall panel (day 6)
Metric Profile-Mullion Mullion / transom profile
Metric Curtain Panel Pattern Based Patterned panel (on a mass surface)
Metric Detail Item 2D detail component

Rule: choose the template by what the family is; the category can be changed later, but the host (face, wall, none) cannot.

3. Family Editor (1 hour)

  1. Create tab: where the family geometry is created.
  2. Forms: Extrusion, Blend, Revolve, Sweep, Swept Blend and Void (day 4).
  3. Datum: Reference Line and Reference Plane (day 2).
  4. Family Editor panel: Load into Project (day 7).
  5. Properties: the family category (here Generic Models).
  6. Family options: Work Plane-Based, Always vertical, Shared, Cut with Voids When Loaded.
  7. Project Browser: the family's own views: Ref. Level plan, 3D, Front/Back/Left/Right.

The template comes with two perpendicular reference planes: Center (Left/Right) and Center (Front/Back). Their intersection is the point the cursor holds when the family is placed in a project. Do not delete or move these two planes.

4. Family category and parameters (30 min)

Create > Properties > Family Category and Parameters:

  1. Category: Generic Models, Curtain Panels, Specialty Equipment... The category decides how the family behaves in schedules, visibility (VV), filters and IFC.
  2. Work Plane-Based: the family is placed on a work plane (for sloped faces).
  3. Always vertical: stays vertical even on a sloped plane.
  4. Shared: whether it counts as a separate element in the project when nested (day 6).

Typical choice for a facade bracket: Generic Models (or the category in your company standard), Work Plane-Based on.

End-of-day check (15 min)

DAY 02

Skeleton

~3.5 h · 0/5 checks

Goal

By the end of the day you will be able to build the "skeleton" of a family: reference planes, dimensions, EQ, labelled dimensions, locking and the flex test. This is the most important day for parametric families. About 3.5 hours.

1. Skeleton first, geometry second (30 min)

Rule: dimension reference planes, not geometry, and lock the geometry to those planes. Even if the geometry is deleted and redrawn, the skeleton and parameters remain.

  1. Draw planes with Create > Datum > Reference Plane.
  2. Give each plane a name in Properties (Left, Right, Top, Bottom, Front, Back). Named planes make choosing work planes and finding errors much easier.
  3. Use a Reference Line for angular parameters and for arms that rotate about their end points.

2. Dimension, EQ and label (1 hour)

  1. Place a dimension between two planes with Annotate > Aligned Dimension.
  2. EQ: dimension three planes (Left, Center, Right) in one string and click the EQ symbol; the middle plane always stays in the middle. The family then flexes symmetrically about the centre.
  3. Label: select the overall dimension → Label Dimension on the ribbon → Create Parameter → name: Width, Type or Instance (day 3).
  4. Do the same for the height: Height.

Note: planes other than the insertion point (the Center planes) are the ones that move. If you want the left edge of the family to stay fixed, you can make the left plane the origin by turning on its Defines Origin property.

3. Is Reference (30 min)

A reference plane's Is Reference property decides whether the plane can be dimensioned to and aligned to once the family is placed in a project. Mark edge planes (Left, Right, Top, Bottom) and important axes; set helper planes to Not a Reference so they do not confuse users in the project.

4. Locking (45 min)

  1. Draw the geometry (in detail on day 4). Draw edges close to the planes.
  2. Modify > Align (AL): first pick the plane, then the edge of the geometry → close the padlock.
  3. Or, in sketch mode, align the line to the plane and lock it.
  4. Never dimension the geometry directly; dimensions belong between planes.

5. Flex test (30 min)

  1. Open Family Types (day 3) and try Width values such as 1200, 2000, 300; Apply.
  2. Does the geometry flex with the planes? If not, an edge is not locked.
  3. Error "Constraints are not satisfied": two locks conflict; remove the last lock you added.
  4. Flex after every new dimension and lock. Finding the error in the last change is much easier than after 20 changes.

End-of-day check (15 min)

DAY 03

Parameters

~3.5 h · 0/5 checks

Goal

By the end of the day you will be able to use the Family Types dialog and know the difference between type and instance parameters, the parameter kinds (family, shared), data types and grouping. About 3 hours.

1. Family Types dialog (45 min)

Create > Properties > Family Types (also on the Modify tab):

  1. New type: add types such as B100, B150; each type has its own values.
  2. New parameter.
  3. Formula column: the value is calculated from other parameters (day 5).
  4. Lock: locks the parameter; it cannot be changed in the project.
  5. Manage Lookup Tables: reading values from a table (day 5).
  6. IFC parameters from the template: which IFC class the family exports to (day 7).

2. Type or instance? (45 min)

Question Answer
Is this value the same for all elements of the type? Type
Can it be different for each placement? Instance
Are schedules and orders made by type? Type
Will it be dragged in the project (e.g. a length)? Instance

For a facade bracket: arm length, thickness, material → Type (each of B100, B150 is a product). Installation level, adjustment → Instance.

Too many instance parameters mean elements of the same type with different sizes, which confuses schedules. When in doubt, choose Type.

3. Parameter properties (45 min)

  1. Parameter type: in the Family Editor, Family parameter or Shared parameter.
  2. Type / Instance.
  3. Name: short names without spaces make formulas easier: Arm_Length, Thickness.
  4. Discipline and data type: Length, Number, Integer, Angle, Yes/No, Material, Text, Area, Mass...
  5. Group parameter under: the heading it appears under in Properties (Dimensions, Materials and Finishes, Identity Data).

4. Shared parameters (30 min)

If a value must appear in a schedule or a tag, a family parameter is not enough; you need a shared parameter. Shared parameters are defined in a .txt file; if the same file is used across all families and projects, the parameter is the same everywhere.

  1. Manage > Shared Parameters: select or create the file, add groups and parameters.
  2. In the Family Editor: new parameter → Shared parameter → Select → pick from the list.
  3. Keep the company shared parameter file in one place; personal copies create parameters with the same name but different identities, and schedules will not combine.

End-of-day check (15 min)

DAY 04

Forms

~3.5 h · 0/5 checks

Goal

By the end of the day you will be able to use the five solid forms and void forms, tie forms to planes, add a material parameter and set visibility by detail level. About 3.5 hours.

1. Forms (1.5 hours)

Form How Facade example
Extrusion Extrude a closed sketch in one direction Bracket plate, panel, glass
Blend Join two different sketches (bottom and top) Tapered cap, transition piece
Revolve Revolve a sketch around an axis Anchor, bolt head, round vent
Sweep Sweep a profile along a path Edge profile, drip, gasket
Swept Blend Transition between two profiles along a path Curved, variable section part

For each form:

  1. First set the work plane (Work Plane > Set): Ref. Level or a named reference plane.
  2. In the sketch, align and lock lines to reference planes (day 2).
  3. Lock the extrusion's Extrusion Start / End to planes or tie them to a parameter (Thickness).
  4. Finish (green tick) and flex.

2. Void forms (30 min)

Void Forms remove material from solids: holes, slots, chamfers. A void cuts solids in the same family automatically when they intersect; if not, use Modify > Cut Geometry. Used for bracket holes, gasket grooves and corner chamfers.

If Cut with Voids When Loaded is on in the family options, a void inside the family can also cut another element in the project (e.g. a wall).

3. Material (30 min)

  1. Select the form → Properties > Materials and Finishes > Material.
  2. The small Associate Family Parameter button at the right of the row → Add parameter → Material, Type.
  3. In the project, the material is chosen in the type properties: aluminium, stainless steel, galvanised steel.

Tie the material to a parameter instead of picking it directly on the form, so the same family can be used with different materials.

4. Visibility and detail level (45 min)

  1. Select the form → Visibility Settings (Family Element Visibility Settings): which view types (plan, section/elevation) and which detail levels (Coarse, Medium, Fine) show it.
  2. Show fine geometry (screws, gaskets, small chamfers) only at Fine; a simple box is enough at Coarse. Performance of big models depends heavily on this.
  3. Tie the Visible property to a Yes/No parameter, e.g. Has_Mid_Transom (can also be driven by a formula on day 5).
  4. If the family looks cluttered in plan, hide the 3D geometry in plan and draw a simple symbol with Symbolic Lines.

End-of-day check (15 min)

DAY 05

Formulas

~3.5 h · 0/5 checks

Goal

By the end of the day you will be able to link parameters with formulas and use conditional (if) formulas, Yes/No logic, rounding and lookup tables. About 3 hours.

1. Formula rules (45 min)

Formulas are written in the Formula column of Family Types.

Rule Example
Parameter names are case-sensitive Width ≠ width
Units must be consistent Width / 2 ✓; Width + 5 ✗, Width + 5 mm ✓
Length / length = number Width / 300 mm → 5
A parameter with a formula cannot be edited by hand Its value is greyed out
Circular references are not allowed A = B, B = A gives an error

2. Conditions and rounding (1 hour)

Function Syntax Example
Condition if(condition, if true, if false) if(Width > 1200 mm, 3, 2)
And / or / not and(a, b), or(a, b), not(a) and(Width > 600 mm, Height > 600 mm)
Down / up / nearest rounddown(x), roundup(x), round(x) rounddown(Width / 300 mm) + 1
Yes/No formula the condition itself Mid_Transom = Width > 1200 mm
Nested if if(a, x, if(b, y, z)) three-range choices

The values in the table are calculated for Width = 1500 mm: since 1500 > 1200 the number of divisions is 3, the spacing 1500 / 3 = 500 mm; screw count rounddown(1500 / 300) + 1 = 5 + 1 = 6.

Note: inside if, the second and third values must have the same unit (both lengths or both numbers).

3. Visibility with Yes/No (30 min)

  1. Mid_Transom (Yes/No, formula: Width > 1200 mm).
  2. Tie the mid transom form's Visible property to Mid_Transom (day 4).
  3. Flex: width 1000 → the transom disappears; 1500 → it appears.

4. Lookup tables (30 min)

To read values from a product catalogue (e.g. profile code → depth, weight) from a CSV table:

  1. Prepare the CSV with the header format Revit expects (column name and unit: Depth##length##millimeters).
  2. Family Types > Manage Lookup Tables > Import.
  3. Formula: size_lookup(TableName, "Depth", 50 mm, Profile_Code): table, column, default if not found, lookup value.

Lookup tables are ideal for driving dozens of types from a catalogue instead of typing them by hand. Another option for many types is a type catalog (a .txt with the same name as the family), which lets the user pick types when loading into the project.

End-of-day check (15 min)

DAY 06

Nested and arrays

~3.5 h · 0/4 checks

Goal

By the end of the day you will be able to build nested families, pass parameters from the host family to the nested one, make a parametric array and create a curtain wall panel family. About 3.5 hours.

1. Nested families (1 hour)

Loading a family inside another lets you make repeating parts (bracket, screw, vent) once and reuse them everywhere.

  1. Open the bracket family → Load into Project into the panel family and place it; or in the panel family use Insert > Load Family.
  2. Align and lock the nested family to planes.
  3. To drive a nested parameter from the host: select the nested family → in Properties (instance parameter) or Edit Type (type parameter), the Associate Family Parameter button at the right of the row → pick a host parameter or create a new one.
  4. Associated parameters must have the same data type.

Shared flag: if the nested family is marked Shared in its own file, it can be selected as a separate element in the project, is counted separately in schedules and can be tagged. You need this if you want to take bracket quantities from a bracket schedule rather than from the panel schedule.

2. Parametric array (1 hour)

  1. Place the repeating element (mullion, hole, nested family); lock the first one to the start plane.
  2. Modify > Array: Group and Associate checked, Move To: Last; move the last element to the end plane and lock it.
  3. Select the array count dimension → Label → new Integer parameter: Mullion_Count.
  4. Formula: Mullion_Count = rounddown(Length / 500 mm) + 1.

An array must have at least 2 elements; if the count could drop to 1, limit the formula: if(Length < 1000 mm, 2, rounddown(Length / 500 mm) + 1).

In the figure, Length = 2650 mm: rounddown(2650 / 500) + 1 = 5 + 1 = 6 mullions.

3. Curtain wall panel family (1 hour)

  1. Template Metric Curtain Wall Panel.rft.
  2. The template's Width and Height parameters come from the curtain wall grid when the panel is placed; you do not type values.
  3. Tie the panel frame, glass and nested families to these planes.
  4. Make values such as glass thickness and frame depth type parameters.
  5. In the project, change the curtain wall's panel type to this family and test by moving grid lines.

Another route for mullions: draw a profile family with Metric Profile-Mullion.rft and assign it as the profile of a mullion type in the project.

4. About adaptive families (15 min)

For irregular facades where every panel is different (warped, triangular), adaptive component families are used; their points are hosted on a mass surface or on free points in the project. This is covered together with Dynamo and Rhino in Parametric Modelling and Rhino.Inside.Revit (in Turkish).

End-of-day check (15 min)

DAY 07

Testing and library

~3.5 h · 0/13 checks

Goal

On the last day you will test the family, load it into a project, run a quality check, save it to the library properly and complete the final exercise. About 4 hours.

1. Test workflow (45 min)

  1. Flex: select every type in Family Types, Apply; is the geometry right?
  2. Extreme values: smallest and largest sizes, the case where the array count is 2.
  3. Load it into an empty test project (not the live project).
  4. Look at it in different views and detail levels (Coarse / Medium / Fine).
  5. Make a schedule: do the shared parameters appear, are nested families counted correctly?
  6. Export to IFC and open it in a viewer: is it in the right class (section 4)?

2. Loading into a project (45 min)

  1. Load into Project: loads the family into the open project; the Family Editor stays open.
  2. Load into Project and Close: loads and closes the editor.
  3. If the family already exists, Revit asks: Overwrite the existing version or Overwrite the existing version and its parameter values. The second replaces type values changed in the project with those of the family.

From the project: Insert > Load Family and pick the .rfa file.

In the project, select the type → Edit Type: the family's type parameters appear here; Duplicate creates a project-specific type. Keeping the company's standard types inside the family is tidier, though.

3. Quality checklist (45 min)

Check Why
Category correct Schedules, filters, IFC
Insertion point makes sense Alignment in the project
All geometry locked to planes No flex errors
Unneeded planes set to Not a Reference No clutter in the project
Simple at Coarse, detailed at Fine Performance
Parameter names follow the standard Formulas and schedules
Shared parameters from the company file Schedules combine
Purge Unused (Manage) done File size
Nested families clean too File size
File size reasonable If large, look for imported CAD or unused nested families

Avoid importing CAD into a family: the file grows, the category gets messy and IFC suffers. If you take a profile section from CAD, use it as an underlay, redraw it with lines, then delete the CAD.

4. Name, version and IFC (30 min)

  1. File name: company standard, e.g. FCD_Bracket_L_Aluminium.rfa. Type names: B100, B150.
  2. Know the version you save in: a family saved in Revit 2027 does not open in older versions. Keep the library matched to the project's Revit version.
  3. IFC: the family's IFC class can be set with the Export Type to IFC As and Type IFC Predefined Type parameters in Family Types (e.g. for a bracket IfcDiscreteAccessory with predefined type BRACKET, or the class required by the project's BIM requirements). The right class makes the family recognisable in BIM deliveries (LOD Levels, in Turkish).
