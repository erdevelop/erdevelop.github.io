GÜN 01

Algoritma nedir?

~4 saat · 0/5 kontrol

Hedef

Gün sonunda bir algoritmanın ne olduğunu, iyi bir algoritmanın özelliklerini bilecek; bir problemi sözde kod ve akış şemasıyla tarif edip Python'a çevirebilecek, uç durumları test edebileceksin. Süre yaklaşık 4 saat. Dosya: gun1.py.

Bu kurs hakkında: Algoritmalar, programlamanın dilden bağımsız çekirdeğidir. Burada öğrendiğin yöntemler Python, C#, JavaScript ya da başka bir dilde aynı şekilde çalışır. Her algoritmayı önce şema ve elle izlemeyle anlayacak, sonra Python ile yazacak, son olarak hızını ölçeceksin. Python'un hazır sorted, min gibi fonksiyonlarını bilerek kullanmayıp kendimiz yazacağız; amaç, bu fonksiyonların içinde ne olduğunu anlamak.

1. Algoritma nedir? (45 dk)

Algoritma, bir problemi çözmek için izlenen, sonlu sayıda, açık ve sıralı adımlardır. İyi bir algoritmanın beş özelliği vardır:

Özellik Anlamı
Girdi Sıfır ya da daha fazla girdi alır
Çıktı En az bir sonuç üretir
Açıklık Her adım tek anlamlıdır; "biraz bekle" değil "15 dakika bekle"
Sonluluk Sonlu sayıda adımdan sonra biter
Etkinlik Her adım gerçekten yapılabilir

Aynı problem için birçok algoritma olabilir. Telefon rehberinde "Yılmaz" aramayı düşün: baştan başlayıp tek tek bakmak da bir algoritmadır, ortadan açıp yarısını elemek de. İkisi de doğru sonucu bulur ama biri çok daha hızlıdır. Bu kursun konusu tam olarak budur: doğru ve verimli çözümler.

2. Sözde kod ve akış şeması (1 saat)

Kod yazmadan önce algoritmayı sözde kodla (pseudocode) tarif etmek düşünceyi netleştirir. Sözde kod belirli bir dile bağlı değildir; Türkçe ve kod karışık yazılabilir.

Problem: bir listedeki en büyük sayıyı bul.

EnBüyük(liste):
    eb ← liste[0]
    her x için liste içinde:
        eğer x > eb ise:
            eb ← x
    eb'yi döndür

Aynı algoritma Python'da:

def en_buyuk(liste):
    eb = liste[0]
    for x in liste:
        if x > eb:
            eb = x
    return eb

print(en_buyuk([12, 45, 7, 45, 3, 31]))

45

Sözde koddan Python'a geçiş neredeyse birebirdir. Bu yüzden algoritma tasarlarken dil ayrıntılarını unutup önce adımları düşün.

4. Doğruluk ve uç durumlar (1 saat)

Bir algoritma "çoğu zaman" doğru çalışıyorsa doğru değildir. Her zaman test edilmesi gereken uç durumlar:

  1. Boş girdi: en_buyuk([]) ne yapmalı?
  2. Tek öğe: [7]
  3. Hepsi aynı: [4, 4, 4]
  4. Negatif sayılar: [-5, -2, -9]
  5. Aranan en başta ya da en sonda
def en_buyuk(liste):
    eb = liste[0]
    for x in liste:
        if x > eb:
            eb = x
    return eb

print(en_buyuk([-5, -2, -9]))
print(en_buyuk([]))

-2
IndexError: list index out of range

Negatif sayılarda doğru, ama boş listede çöküyor. Bir yaygın hata da eb = 0 ile başlamaktır: o zaman bütün sayılar negatifse sonuç yanlışlıkla 0 çıkar. Düzeltilmiş hâli:

def en_buyuk(liste):
    if not liste:
        raise ValueError("Liste boş")
    eb = liste[0]
    for x in liste[1:]:
        if x > eb:
            eb = x
    return eb

for test in ([3], [4, 4, 4], [-5, -2, -9], [1, 9, 2]):
    print(test, "→", en_buyuk(test))

[3] → 3
[4, 4, 4] → 4
[-5, -2, -9] → -2
[1, 9, 2] → 9

assert ile test: Beklediğin sonucu koda yazarsan, değişiklik yaptığında algoritmanın bozulup bozulmadığını hemen anlarsın.

def en_buyuk(liste):
    eb = liste[0]
    for x in liste[1:]:
        if x > eb:
            eb = x
    return eb

assert en_buyuk([1, 9, 2]) == 9
assert en_buyuk([-5, -2, -9]) == -2
assert en_buyuk([7]) == 7
print("Bütün testler geçti.")

Bütün testler geçti.

Alıştırma: Aynı yöntemle bir listedeki ikinci en büyük farklı sayıyı bulan algoritmayı önce sözde kodla, sonra Python ile yaz. Uç durumları düşün: [5, 5, 3] için cevap 3, [5, 5] için cevap yok.

GÜN 02

Karmaşıklık ve Big-O

~4 saat · 0/5 kontrol

Hedef

Gün sonunda bir algoritmanın girdi büyüdükçe nasıl yavaşladığını Big-O gösterimiyle ifade edebilecek, yaygın karmaşıklık sınıflarını tanıyacak ve iki çözümün hızını Python'da ölçüp karşılaştırabileceksin. Süre yaklaşık 4 saat.

1. Neden hız önemli? (30 dk)

100 öğelik bir listede hangi algoritmayı kullandığın pek fark etmez; her şey göz açıp kapayıncaya kadar biter. Ama 10 milyon öğede bir algoritma 1 saniyede biterken diğeri günlerce sürebilir. Algoritmaları karşılaştırırken saniye değil, girdi büyüdükçe adım sayısının nasıl arttığını ölçeriz. Çünkü saniye bilgisayara göre değişir, artış hızı değişmez.

2. Adım saymak (1 saat)

Bir listede bir sayının olup olmadığına bakalım:

def var_mi(liste, aranan):
    adim = 0
    for x in liste:
        adim += 1
        if x == aranan:
            return True, adim
    return False, adim

liste = list(range(1, 1001))
print(var_mi(liste, 1))
print(var_mi(liste, 500))
print(var_mi(liste, 5000))

(True, 1)
(True, 500)
(False, 1000)
  • En iyi durum: aranan en başta, 1 adım.
  • En kötü durum: aranan yok, n adım (n = liste uzunluğu).
  • Ortalama: yaklaşık n/2 adım.

Algoritmaları genelde en kötü duruma göre değerlendiririz, çünkü bu bir garantidir: "ne olursa olsun en fazla n adım".

Şimdi bir listede aynı iki sayı var mı sorusuna bakalım:

def tekrar_var_mi(liste):
    adim = 0
    n = len(liste)
    for i in range(n):
        for j in range(i + 1, n):
            adim += 1
            if liste[i] == liste[j]:
                return True, adim
    return False, adim

for n in (10, 100, 1000):
    print(n, tekrar_var_mi(list(range(n))))

10 (False, 45)
100 (False, 4950)
1000 (False, 499500)

Girdi 10 kat büyüyünce adım sayısı yaklaşık 100 kat büyüdü. Adım sayısı n × (n − 1) / 2, yani kabaca n²/2.

3. Big-O gösterimi (1 saat)

Big-O, girdi büyüdükçe adım sayısının nasıl arttığını gösteren kaba bir ölçüdür. Sabit çarpanları ve küçük terimleri atarız: n²/2 − n/2 → O(n²). Çünkü n çok büyüdüğünde önemli olan sadece en hızlı büyüyen terimdir.

Big-O Adı Örnek n = 1.000.000 için kabaca
O(1) Sabit Listenin i'nci öğesini okumak, sözlükte anahtar 1 adım
O(log n) Logaritmik Sıralı listede ikili arama 20 adım
O(n) Doğrusal Listede arama, toplam 1 milyon adım
O(n log n) – İyi sıralama algoritmaları 20 milyon adım
O(n²) Karesel İç içe iki döngü 1 trilyon adım
O(2ⁿ) Üstel Bütün alt kümeleri denemek evrenin ömründen uzun

Saniyede 100 milyon basit işlem yapan bir bilgisayarda 1 trilyon adım yaklaşık 3 saat sürer; 20 milyon adım ise 0,2 saniye. İşte bu yüzden algoritma seçimi donanımdan daha önemlidir.

Kısa kurallar:

  1. Tek döngü n kez dönüyorsa: O(n).
  2. İç içe iki döngü, ikisi de n'e bağlıysa: O(n²).
  3. Her adımda problem yarıya iniyorsa: O(log n).
  4. Arka arkaya iki ayrı döngü: O(n) + O(n) = O(n). Toplamda en büyük terim kalır.

4. Ölçmek (1 saat)

tekrar_var_mi problemini daha akıllı çözebiliriz. Gördüğümüz sayıları bir küme (set) içinde tutarsak, bir sayının daha önce görülüp görülmediğini tek adımda öğreniriz (bunun nasıl mümkün olduğunu Veri Yapıları eğitiminde göreceğiz):

def tekrar_var_mi_hizli(liste):
    gorulen = set()
    for x in liste:
        if x in gorulen:
            return True
        gorulen.add(x)
    return False

print(tekrar_var_mi_hizli([3, 8, 1, 8]))
print(tekrar_var_mi_hizli([3, 8, 1]))

True
False

Bu O(n)'dir. İki sürümün hızını time.perf_counter ile ölçelim:

import time

def yavas(liste):
    n = len(liste)
    for i in range(n):
        for j in range(i + 1, n):
            if liste[i] == liste[j]:
                return True
    return False

def hizli(liste):
    gorulen = set()
    for x in liste:
        if x in gorulen:
            return True
        gorulen.add(x)
    return False

for n in (1000, 2000, 4000):
    liste = list(range(n))
    t0 = time.perf_counter(); yavas(liste); t1 = time.perf_counter(); hizli(liste); t2 = time.perf_counter()
    print(f"n={n:5}  yavaş {t1 - t0:.4f} sn   hızlı {t2 - t1:.5f} sn")

Benim bilgisayarımdaki tipik sonuç:

n= 1000  yavaş 0.0180 sn   hızlı 0.00004 sn
n= 2000  yavaş 0.0720 sn   hızlı 0.00008 sn
n= 4000  yavaş 0.2900 sn   hızlı 0.00016 sn

n her iki katına çıktığında yavaş sürüm 4 kat, hızlı sürüm 2 kat yavaşlıyor. O(n²) ve O(n)'nin tam olarak beklediğimiz davranışı. Senin sayıların farklı olacak; oranlara bak.

5. Bellek de bir maliyettir (15 dk)

Hızlı sürüm, gördüğü sayıları bir kümede sakladığı için ekstra bellek kullandı: O(n) bellek. Yavaş sürüm ise O(1) bellek kullanır. Algoritmalarda sık görülen bir alışveriştir: bellek harcayıp zaman kazanmak. Günümüz bilgisayarlarında bellek genelde ucuzdur, ama milyarlarca kayıtta bu da önemli olur.

Alıştırma: Aşağıdaki fonksiyonların Big-O'sunu bul. (Cevaplar: O(n), O(n²), O(1), O(log n))

  1. Bir listenin toplamını hesaplayan döngü.
  2. Bir n × n tablonun bütün hücrelerini yazan iç içe döngü.
  3. Listenin son öğesini döndüren liste[-1].
  4. while n > 1: n = n // 2 döngüsü.

GÜN 03

Arama

~4 saat · 0/5 kontrol

Hedef

Gün sonunda doğrusal ve ikili aramayı yazabilecek, ikili aramanın neden O(log n) olduğunu açıklayabilecek, Python'un bisect modülünü kullanabilecek ve ikili arama fikrini sayısal problemlere uygulayabileceksin. Süre yaklaşık 4 saat. Dosya: gun3.py.

1. Doğrusal arama (30 dk)

En basit arama: baştan sona tek tek bak. Bulursan konumunu, bulamazsan −1 döndür.

def dogrusal_ara(liste, aranan):
    for i, x in enumerate(liste):
        if x == aranan:
            return i
    return -1

sehirler = ["Adana", "Bursa", "İzmir", "Konya", "Van"]
print(dogrusal_ara(sehirler, "Konya"))
print(dogrusal_ara(sehirler, "Rize"))

3
-1

O(n). Listenin sıralı olması gerekmez; bu onun en büyük avantajıdır. Küçük ya da sıralı olmayan listelerde doğru seçimdir.

2. İkili arama (1,5 saat)

Liste sıralıysa çok daha iyisini yapabiliriz. Ortadaki öğeye bak:

  • Aranan ona eşitse bulundu.
  • Aranan daha küçükse sağ yarıyı tamamen at, sol yarıda ara.
  • Daha büyükse sol yarıyı at, sağ yarıda ara.

Her adımda arama alanı yarıya iner.

def ikili_ara(liste, aranan):
    sol, sag = 0, len(liste) - 1
    adim = 0
    while sol <= sag:
        adim += 1
        orta = (sol + sag) // 2
        if liste[orta] == aranan:
            return orta, adim
        elif liste[orta] < aranan:
            sol = orta + 1
        else:
            sag = orta - 1
    return -1, adim

sayilar = [3, 8, 15, 21, 27, 34, 42, 56, 61, 77, 89]
print(ikili_ara(sayilar, 61))
print(ikili_ara(sayilar, 20))

(8, 2)
(-1, 3)

import bisect

sinirlar = [45, 55, 70, 85]

4. Cevabı ikili aramayla bulmak (1 saat)

İkili arama sadece listelerde değil, cevabı bir aralıkta olan her problemde işe yarar. Koşul şu: "x yeterliyse x'ten büyük her değer de yeterlidir" gibi tek yönlü bir özellik olmalı.

Örnek: Bir sayının karekökünü math.sqrt kullanmadan 6 basamak hassasiyetle bulalım:

def karekok(a, hassasiyet=1e-6):
    sol, sag = 0.0, max(1.0, a)
    adim = 0
    while sag - sol > hassasiyet:
        adim += 1
        orta = (sol + sag) / 2
        if orta * orta < a:
            sol = orta
        else:
            sag = orta
    return round((sol + sag) / 2, 6), adim

print(karekok(2))
print(karekok(1_000_000))

(1.414214, 21)
(1000.0, 40)

Bir milyonun karekökünü 40 adımda, 6 basamak hassasiyetle bulduk.

Gerçek hayattan bir örnek: 12 m'lik bir kirişin sehimi yük arttıkça artar. "Sehim 30 mm'yi geçmeden taşınabilecek en büyük yük ne?" sorusu tam olarak bu kalıptır: yükü bir aralıkta ikili aramayla ararsın.

Alıştırma:

  1. ikili_ara fonksiyonunu, aranan sayı listede birden fazla kez varsa ilkinin konumunu döndürecek şekilde değiştir. (İpucu: bulunca hemen dönme; sonucu kaydet ve sola doğru aramaya devam et.)
  2. Aylık 2.500 TL ödemeyle, aylık %2,5 faizle 60 ayda ödenebilecek en büyük kredi tutarını ikili aramayla bul.

GÜN 04

Sıralama

~4 saat · 0/4 kontrol

Hedef

Gün sonunda üç sıralama algoritmasını (seçmeli, eklemeli, birleştirmeli) yazıp elle izleyebilecek, hangisinin neden daha hızlı olduğunu açıklayabilecek, kararlılık kavramını bilecek ve Python'un sorted fonksiyonunu key ile ustaca kullanabileceksin. Süre yaklaşık 4 saat. Dosya: gun4.py.

1. Seçmeli sıralama (45 dk)

Fikir: Listenin en küçüğünü bul, en başa koy. Kalanların en küçüğünü bul, ikinci sıraya koy. Böyle devam et.

def secmeli_sirala(liste):
    a = liste[:]                       # orijinali bozmamak için kopya
    n = len(a)
    for i in range(n - 1):
        en_kucuk = i
        for j in range(i + 1, n):
            if a[j] < a[en_kucuk]:
                en_kucuk = j
        a[i], a[en_kucuk] = a[en_kucuk], a[i]
        print(f"tur {i + 1}: {a}")
    return a

secmeli_sirala([29, 10, 14, 37, 13])

tur 1: [10, 29, 14, 37, 13]
tur 2: [10, 13, 14, 37, 29]
tur 3: [10, 13, 14, 37, 29]
tur 4: [10, 13, 14, 29, 37]
  • a[i], a[j] = a[j], a[i] Python'da iki değeri yer değiştirmenin kısa yoludur.
  • Her turda sol taraf sıralı bölge olarak büyür.
  • İç içe iki döngü: O(n²). Liste zaten sıralı olsa bile aynı sayıda karşılaştırma yapar.

2. Eklemeli sıralama (45 dk)

Fikir: Elindeki iskambil kartlarını sıralamak gibi. Her yeni kartı, solundaki sıralı kartların arasında doğru yere kaydırarak yerleştir.

def eklemeli_sirala(liste):
    a = liste[:]
    for i in range(1, len(a)):
        anahtar = a[i]
        j = i - 1
        while j >= 0 and a[j] > anahtar:
            a[j + 1] = a[j]           # büyükleri bir sağa kaydır
            j -= 1
        a[j + 1] = anahtar
        print(f"{anahtar:>2} yerleşti: {a}")
    return a

3. Birleştirmeli sıralama (1,5 saat)

O(n²)'den kurtulmanın yolu böl ve yönet:

  1. Listeyi iki yarıya böl.
  2. Her yarıyı (aynı yöntemle) sırala.
  3. İki sıralı yarıyı birleştir.

Birleştirme adımı kolaydır: iki sıralı listenin başlarına bak, küçük olanı al, devam et.

def birlestir(sol, sag):
    sonuc = []
    i = j = 0
    while i < len(sol) and j < len(sag):
        if sol[i] <= sag[j]:
            sonuc.append(sol[i]); i += 1
        else:
            sonuc.append(sag[j]); j += 1
    sonuc.extend(sol[i:])
    sonuc.extend(sag[j:])
    return sonuc

def birlestirmeli_sirala(liste):
    if len(liste) <= 1:
        return liste
    orta = len(liste) // 2
    return birlestir(birlestirmeli_sirala(liste[:orta]), birlestirmeli_sirala(liste[orta:]))

print(birlestir([10, 14, 29], [13, 37]))
print(birlestirmeli_sirala([38, 27, 43, 3, 9, 82, 10]))

[10, 13, 14, 29, 37]
[3, 9, 10, 27, 38, 43, 82]

Fonksiyonun kendini çağırmasına özyineleme denir; yarın ayrıntılı göreceğiz.

Neden O(n log n)? Liste log₂ n kez yarıya bölünür (şemadaki kat sayısı). Her katta bütün öğeler bir kez birleştirilir: n iş. Toplam: n × log n. 1 milyon öğede bu, n²'ye göre yaklaşık 50.000 kat daha az iştir.

1. Özyineleme nedir? (1 saat)

Özyineleme (recursion), bir fonksiyonun problemi kendisinin daha küçük bir kopyasına indirgeyerek çözmesidir. Her özyinelemeli fonksiyonun iki parçası vardır:

  1. Temel durum: Cevabı doğrudan bilinen en küçük problem. Burada fonksiyon kendini çağırmaz.
  2. Özyinelemeli adım: Problemi küçültüp fonksiyonu tekrar çağırmak.

Klasik örnek: faktöriyel. 5! = 5 × 4!, 4! = 4 × 3!, … ve 0! = 1.

def faktoriyel(n):
    if n == 0:              # temel durum
        return 1
    return n * faktoriyel(n - 1)   # özyinelemeli adım

print(faktoriyel(5))
print(faktoriyel(20))

2432902008176640000

Çağrı yığını: faktoriyel(5) çağrıldığında, faktoriyel(4) bitene kadar bekler; o da faktoriyel(3)'ü bekler… Bekleyen çağrılar bir yığın gibi üst üste birikir. faktoriyel(0) 1 döndürünce yığın tersine çözülür: 1, 1, 2, 6, 24, 120.

Temel durumu unutursan fonksiyon sonsuza kadar kendini çağırır. Python bunu yaklaşık 1000 çağrıda durdurur:

4. Böl ve yönet (1 saat)

Hanoi kuleleri: Üç çubuk ve büyükten küçüğe dizili n disk. Bütün diskleri A'dan C'ye taşı; bir seferde bir disk ve büyük disk küçüğün üstüne konamaz.

Özyinelemeli düşünce: n diski A'dan C'ye taşımak için, (1) üstteki n−1 diski B'ye taşı, (2) en büyük diski C'ye taşı, (3) n−1 diski B'den C'ye taşı.

def hanoi(n, kaynak, hedef, yardimci, hamleler):
    if n == 0:
        return
    hanoi(n - 1, kaynak, yardimci, hedef, hamleler)
    hamleler.append(f"{n}: {kaynak}→{hedef}")
    hanoi(n - 1, yardimci, hedef, kaynak, hamleler)

hanoi(3, "A", "C", "B", h)

n disk için 2ⁿ − 1 hamle gerekir. 64 disk için, saniyede bir hamleyle, yaklaşık 585 milyar yıl.

Hızlı üs alma: 3¹⁰⁰⁰ hesaplamak için 1000 çarpma gerekmez. xⁿ = (x^(n/2))² olduğunu kullan:

def us(x, n):
    if n == 0:
        return 1
    yarim = us(x, n // 2)
    return yarim * yarim if n % 2 == 0 else yarim * yarim * x

2. Dinamik programlama (1,5 saat)

Dinamik programlama (DP), problemi küçük alt problemlere bölüp her birinin cevabını bir tabloya yazar ve büyük cevabı bu tablodan kurar. Dün gördüğün memoization'ın düzenli hâlidir.

Para üstü için: en_az[t] = t tutarı için gereken en az para sayısı. Her t için her parayı dene: o parayı kullanırsan geriye t − p kalır, onun cevabı zaten tabloda.

en_az[t] = min(en_az[t − p] + 1), bütün p ≤ t paraları için.

def dp_para(tutar, paralar):
    SONSUZ = float("inf")
    en_az = [0] + [SONSUZ] * tutar
    son_para = [0] * (tutar + 1)
    for t in range(1, tutar + 1):
        for p in paralar:
            if p <= t and en_az[t - p] + 1 < en_az[t]:
                en_az[t] = en_az[t - p] + 1
                son_para[t] = p
    # hangi paraları kullandığımızı geriye doğru bul
    sonuc, t = [], tutar
    while t > 0:
        sonuc.append(son_para[t])
        t -= son_para[t]
    return en_az[:tutar + 1], sonuc

tablo, cozum = dp_para(6, [1, 3, 4])
print("tablo:", tablo)
print("çözüm:", cozum)

tablo: [0, 1, 2, 1, 1, 2, 2]
çözüm: [3, 3]

Tabloyu elle izle: en_az[6] = min(en_az[5] + 1, en_az[3] + 1, en_az[2] + 1) = min(3, 2, 3) = 2. Doğru cevap. Maliyet: O(tutar × para sayısı).

DP tarifi:

  1. Alt problemi tanımla (en_az[t] ne demek?).
  2. Küçükten büyüğe ilişkiyi yaz (formül).
  3. Temel durumu belirle (en_az[0] = 0).
  4. Tabloyu doldur, cevabı oku; gerekirse çözümü geriye doğru kur.

def sirt_cantasi(esyalar, kapasite):
    n = len(esyalar)
    # T[i][k]: ilk i eşyayla, k kapasitede en büyük değer
    T = [[0] * (kapasite + 1) for _ in range(n + 1)]
    for i in range(1, n + 1):
        ad, w, v = esyalar[i - 1]
        for k in range(kapasite + 1):
            T[i][k] = T[i - 1][k]                          # bu eşyayı alma
            if w <= k:
                T[i][k] = max(T[i][k], T[i - 1][k - w] + v)  # al
    secilen, k = [], kapasite
    for i in range(n, 0, -1):
        if T[i][k] != T[i - 1][k]:
            secilen.append(esyalar[i - 1][0])
            k -= esyalar[i - 1][1]
    return T[n][kapasite], secilen[::-1]

4. Çubuk kesme (30 dk)

def cubuk_kes(n):
    en_iyi = [0] * (n + 1)
    kesim = [0] * (n + 1)
    for u in range(1, n + 1):
        for parca in range(1, u + 1):
            if fiyat[parca] + en_iyi[u - parca] > en_iyi[u]:
                en_iyi[u] = fiyat[parca] + en_iyi[u - parca]
                kesim[u] = parca
    parcalar = []
    while n > 0:
        parcalar.append(kesim[n]); n -= kesim[n]
    return en_iyi[-1], parcalar

2. BFS: genişlik öncelikli arama (1 saat)

BFS, başlangıç düğümünden katman katman yayılır: önce bütün komşular, sonra komşuların komşuları… Bir kuyruk kullanır: ilk giren ilk çıkar.

En önemli özelliği: ağırlıksız bir grafta en az kenarlı yolu bulur.

from collections import deque

graf = {"A": ["B", "C"], "B": ["A", "D", "E"], "C": ["A", "F"],
        "D": ["B"], "E": ["B", "F"], "F": ["C", "E"]}

def bfs_yol(graf, bas, hedef):
    kuyruk = deque([bas])
    onceki = {bas: None}
    while kuyruk:
        d = kuyruk.popleft()
        if d == hedef:
            break
        for k in graf[d]:
            if k not in onceki:
                onceki[k] = d
                kuyruk.append(k)
    yol, d = [], hedef
    while d is not None:
        yol.append(d); d = onceki[d]
    return yol[::-1], list(onceki)

yol, ziyaret = bfs_yol(graf, "A", "F")
print("ziyaret sırası:", ziyaret)
print("en kısa yol:", " → ".join(yol))

ziyaret sırası: ['A', 'B', 'C', 'D', 'E', 'F']
en kısa yol: A → C → F

onceki sözlüğü iki iş görür: bir düğümün ziyaret edildiğini işaretler ve oraya nereden gelindiğini hatırlar; böylece yolu geriye doğru kurarız. O(düğüm + kenar).

3. DFS: derinlik öncelikli arama (45 dk)

DFS bir yolu sonuna kadar izler, çıkmaza girince geri döner. Labirentte sağ eli duvardan ayırmadan yürümek gibi. Özyinelemeyle çok doğal yazılır:

graf = {"A": ["B", "C"], "B": ["A", "D", "E"], "C": ["A", "F"],
        "D": ["B"], "E": ["B", "F"], "F": ["C", "E"]}

def dfs(graf, d, ziyaret=None):
    if ziyaret is None:
        ziyaret = []
    ziyaret.append(d)
    for k in graf[d]:
        if k not in ziyaret:
            dfs(graf, k, ziyaret)
    return ziyaret

print(dfs(graf, "A"))

['A', 'B', 'D', 'E', 'F', 'C']

DFS en kısa yolu garanti etmez ama "bu iki nokta bağlı mı?", "grafta döngü var mı?", "kaç ayrı parça var?" gibi sorular için idealdir.

4. Dijkstra: ağırlıklı en kısa yol (1 saat)

Kenarların uzunlukları farklıysa (km, dakika, maliyet), en az kenarlı yol en kısa yol değildir. Dijkstra algoritması her adımda, başlangıca bilinen en yakın düğümü kesinleştirir ve komşularının mesafelerini günceller. En yakını hızlıca bulmak için bir öncelik kuyruğu (heapq) kullanır.

import heapq

yollar = {
    "Ev":     {"Okul": 4, "Market": 2},
    "Market": {"Okul": 1, "Park": 7},
    "Okul":   {"Park": 3, "Hastane": 8},
    "Park":   {"Hastane": 2},
    "Hastane": {},
}

def dijkstra(graf, bas):
    mesafe = {d: float("inf") for d in graf}
    onceki = {bas: None}
    mesafe[bas] = 0
    kuyruk = [(0, bas)]
    while kuyruk:
        m, d = heapq.heappop(kuyruk)
        if m > mesafe[d]:
            continue                      # eski, geçersiz kayıt
        for k, w in graf[d].items():
            if m + w < mesafe[k]:
                mesafe[k] = m + w
                onceki[k] = d
                heapq.heappush(kuyruk, (mesafe[k], k))
    return mesafe, onceki

mesafe, onceki = dijkstra(yollar, "Ev")
print(mesafe)
yol, d = [], "Hastane"
while d:
    yol.append(d); d = onceki[d]
print(" → ".join(reversed(yol)), mesafe["Hastane"], "dk")

{'Ev': 0, 'Market': 2, 'Okul': 3, 'Park': 6, 'Hastane': 8}
Ev → Market → Okul → Park → Hastane 8 dk

Ev'den Okul'a doğrudan yol 4 dakika, ama Market üzerinden 2 + 1 = 3. Dijkstra bunu buldu. Hastane'ye Okul'dan doğrudan gitmek 3 + 8 = 11; Park üzerinden 3 + 3 + 2 = 8. ✓

Dijkstra negatif ağırlıklı kenarlarda çalışmaz (ona Bellman–Ford gerekir). Navigasyon uygulamaları Dijkstra'nın hızlandırılmış hâllerini (A* gibi) kullanır.

5. Topolojik sıralama (30 dk)

Bir proje planında bazı işler diğerlerinden önce bitmeli. Hangi sırayla yapmalı? Bu, yönlü ve döngüsüz bir grafın topolojik sıralamasıdır:

from graphlib import TopologicalSorter

oncekiler = {
    "temel": [],
    "kolon": ["temel"],
    "döşeme": ["kolon"],
    "cephe": ["döşeme"],
    "tesisat": ["döşeme"],
    "boya": ["cephe", "tesisat"],
}
print(list(TopologicalSorter(oncekiler).static_order()))

['temel', 'kolon', 'döşeme', 'cephe', 'tesisat', 'boya']

Python 3.9'dan beri graphlib modülü hazırdır. İçeride yaptığı şu: önkoşulu kalmamış işleri sıraya al, onları listeden çıkar, yeni önkoşulsuz kalanları bul, tekrarla. Grafta döngü varsa (A, B'yi bekliyor; B, A'yı) CycleError verir; bu da plandaki bir mantık hatasını yakalamanın yoludur.
